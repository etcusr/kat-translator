# macOS integration, 2026-10-10

Defaults from Mac0.3.3/build45: Option+1 selected text, Option+2 screen region, Option+3 clipboard text, in that order in Settings and menus. These were explicitly chosen by the user in place of Control+Shift+T/S/V. Existing custom or disabled bindings remain stored; reset restores the new defaults. Settings allow arbitrary modifier count, including all four modifiers plus a key. All Kat-defined action shortcuts can be reassigned or disabled. Shift+Enter always inserts a newline. The Option+digit defaults intercept those combinations' special-character input while registered.

Conflict research: [Apple](https://support.apple.com/en-us/102650), [Chrome Mac section](https://support.google.com/chrome/answer/157179?co=GENIE.Platform%3DDesktop&hl=en), [Safari](https://support.apple.com/en-lamr/guide/safari/cpsh003/mac), [Telegram macOS](https://github.com/overtake/TelegramSwift/blob/master/Telegram-Mac/ShortcutListController.swift), [Telegram Desktop](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/core/shortcuts.cpp). The former Control+Shift+T/S/V were absent from these Mac default lists. Qt uses `ctrl` for Command and `meta` for Control on Mac. Earlier Option+Command+T/S/V choices conflict with toolbar/sidebar/move-file commands. Runtime checks enabled macOS symbolic shortcuts, known application defaults, duplicate bindings, and Carbon registration failures. Option+2 through Option+5 were assigned in this Mac's system settings when the new defaults were chosen; the user will reassign those OS commands themselves. Kat does not alter or bypass system assignments. Restart Kat after changing those assignments to retry registration. This cannot guarantee absence of custom browser-extension or other-app bindings.

Selection first reads AXSelectedText or the selected text-marker range from the focused element and its bounded ancestor chain, only on explicit action. For apps that do not expose selection (e.g. custom editors/browser pages), it invokes the app’s standard Copy command, accepts only a fresh text update, and restores the previous clipboard formats. Secure input is excluded; unchanged clipboard contents are never treated as selected text. A newer user copy is not overwritten. Clipboard translation remains a separate explicit command. Services consumes the supplied pasteboard. External text opens the main window in Text mode, replaces its draft/results, and uses the normal text translation, speech and history path. It rejects concurrent operations. No separate quick window is created; the main Cancel action also cancels an external request.

Screen capture uses per-display local coordinates and Retina scale, sends only the selected image to Image after the tab acknowledges the request, and preserves previous content on cancellation. Permissions are requested on the first use of the respective selection or screen-region action; startup and clipboard/Services do not prompt. Settings also provides explicit permission controls. No permission is needed for clipboard/Services.

Screen permission requests go through ScreenCaptureKit `SCShareableContent`, because the legacy CoreGraphics request returned denied without adding the app on the test Mac. The main window checks actual AX/CoreGraphics grants periodically, clearing only permission-related messages when access is granted. A regression covers independent grants and preservation of unrelated errors/drafts. TCC logs confirmed that old ad-hoc grants still referred to prior executable hashes after toggling; packaging now uses the existing Apple Development identity for a stable designated requirement. The one-time migration initially tried removing/re-adding Kat in System Settings, but this Mac retained the old requirement. The standard `tccutil reset Accessibility org.openoffline.translator.mac` and `tccutil reset ScreenCapture org.openoffline.translator.mac` then reset only Kat grants before first-use prompts were requested again. No direct TCC database edits or automatic grants.

Text sharing passes both text and completed audio. A two-entry temporary cache supports original and translated speech independently even with history disabled. Exact text/language matching prevents stale attachments; incomplete recordings are never exposed. Native sharing services receive a string plus file URL. Messenger fallbacks without caption/file APIs preserve the text as an additional UTF-8 text attachment. Private exports survive macOS picker dismissal and expire after 24 hours when sharing next runs. On normal app termination all app-owned temporary audio and share copies are removed; saved history remains untouched. iOS force-quits may not run a termination callback, so startup also removes leftover temporary files.

Quick translation now uses the onboarding primary language by default (`languageSetup.primaryID`, Russian for the existing pre-onboarding installation). Settings → Shortcuts → Quick translation language optionally stores an override (`quickTranslationTarget`); resetting to Primary follows later onboarding changes. Selected text, clipboard, Services, and screen regions all apply this destination to the main pair when invoked, regardless of its previous target. The current source-language choice is preserved: Auto detects it, while an explicit language bypasses detection. A target unsupported by the current model produces an error rather than silently changing language. In Auto, screen OCR uses Vision automatic language detection, then the bundled text detector identifies the translation source. With an explicit source, Vision receives that language and automatic detection is disabled. See [Apple Vision documentation](https://developer.apple.com/documentation/vision/vnrecognizetextrequest/automaticallydetectslanguage).

Image on Mac displays an editable translation in the right pane, with expand, copy, share and save icons above it. Copy and the expanded reader use the edited text; Share and Save still export the translated PNG from the recognized blocks, independently of freeform text edits. Source remains visible in the image. The iPhone camera retains its overlay; its existing Translation text sheet now has Copy translation in the toolbar. Before editing, clipboard output contains the translated blocks in reading order, separated by blank lines, without originals. Same-language image text is copied without translation inference.

The main searchable language picker can override automatic detection and destination for the current text. A new external request preserves the selected source language or Auto and applies the configured quick target; manual retries keep the chosen pair. Picker changes do not modify the global quick-language preference. The main Text toolbar provides original/translation speech, copy and sharing. Screen-region translation remains in Image. A pending text request starts after Text acknowledges it; completed old screen-capture requests cannot switch a reopened window back to Image.
