Перевод изображений работает с файлами или буфером обмена: OCR, локальный перевод и экспорт PNG. Запись и воспроизведение звука, история, проверка загрузок и интерфейс RU/EN/ES/TR используют общий код. Живой камеры и iOS Live Activity на Mac нет. Свёрнутые и фоновые окна оставляют приложение работать; выход — отдельное действие.

«Авто» — первая строка меню исходного языка в «Голосе», «Тексте» и «Изображении». Выбор конкретного языка отключает определение, в том числе для глобальных горячих клавиш. «Озвучивать автоматически» находится в верхней строке рядом с вкладками режимов.

## Сборка для Mac App Store

Магазинный вариант собирает `scripts/archive-macos-appstore.sh` (`KAT_MAC_STORE_BUILD=<n> scripts/archive-macos-appstore.sh export|upload`). Скрипт генерирует отдельный игнорируемый Xcode-проект в `.build/macos-store-project/`, где только target приложения получает магазинный Bundle ID, магазинный `Info.plist` (версия 1.0, `ITSAppUsesNonExemptEncryption = NO`), `apps/macos/KatMacStore.entitlements` (App Sandbox, микрофон, выбранные пользователем файлы, исходящая сеть) и автоматическую подпись. Ресурсные бандлы SwiftPM сохраняют собственные идентификаторы. Обычный проект и прямая сборка не меняются.

Правила упаковки только для магазина (в `scripts/bundle-macos-runtimes.py`, действуют при `ENABLE_APP_SANDBOX=YES`):

- helper OPUS GPU `Contents/MacOS/OpusPython` и `torch/bin/torch_shm_manager` подписываются с sandbox + inherit; `protoc` не включается;
- реализации TLS/криптографии не поставляются: исключены Python `_ssl`/`_hashlib`, `libssl`/`libcrypto` и `hf_xet` (rustls); `index_mlx.py` подставляет инертный модуль `ssl`, чтобы `mlx_lm` импортировался офлайн;
- у ресурсных бандлов SwiftPM без кода снимается отдельная development-подпись; их запечатывает подпись приложения.

Скрипт останавливается, если в архиве есть XCTest-бандлы, исполняемые файлы без sandbox, ресурсные бандлы с development-подписью, ресурсный бандл с ID приложения или маркеры OpenSSL/rustls/BoringSSL. Подробности, результаты тестов внутри sandbox и история сборок 61–66 — в [отчёте магазинной сборки](../publication/macos-appstore-build-2026-10-14.md).

## Сборка прямого выпуска

На компьютере сборки нужны Xcode, CMake, закреплённые зависимости проекта, Homebrew Python 3.11 для упаковки, подготовленный Python-фронтенд Wayu и ONNX Runtime 1.30.0 в `.build/wayu-env`. **На целевом Mac ничего из этого не требуется**.

1. `bash scripts/build-macos-runtimes.sh`
2. `python3 scripts/generate-macos-project.py`
3. `xcodebuild -project apps/macos/KatTranslatorMac.xcodeproj -scheme KatTranslatorMac -configuration Release -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/MacDerivedData ARCHS=arm64 ONLY_ACTIVE_ARCH=YES build`
4. `bash scripts/package-macos.sh`

Результат: `dist/macos/Kat-translator-<версия>-build<сборка>-mac-arm64.dmg`, ZIP и SHA256SUMS. Сборка включает и перелинковывает несистемные библиотеки, Python и тайский фронтенд. XCTest-бандлы и архивы конфигурации сборки Python исключаются. Аудит упаковки отклоняет зависимости от абсолютных путей библиотек Homebrew/проекта.

Для совместимой загрузки выполните `bash scripts/build-macos15-26.sh` после подготовки современного runtime Index. Скрипт скачивает проверенные по SHA колёса MLX 0.32.2 для macOS 15 и автономный Python 3.11.17, собирает в `.build/MacOS15DerivedData`, добавляет к именам файлов `-macos15-26` и при выходе восстанавливает обычный Xcode-проект. Он не устанавливает приложение и не скачивает веса моделей. Итоговый аудит отклоняет любой компонент, которому нужна ОС новее заявленного минимума.

Прямые сборки используют прежний сертификат Apple Development, **без Developer ID и нотаризации**. Генератор проекта и упаковщик используют `scripts/mac-signing.py`: сохраняют сертификат установленной Kat, если доступен его ключ; если Kat с сертификатной подписью ещё не установлена — выбирают единственный Developer ID Application, затем единственный Apple Development. Отсутствующий ключ установленной версии или неоднозначность останавливает операцию. `KAT_MAC_SIGNING_IDENTITY` явно выбирает сертификат по отпечатку или точному имени. Сгенерированный проект читает отпечаток из игнорируемого `.build/macos-signing.xcconfig`; после нового клонирования сначала нужно запустить генератор. Личные данные сертификата не записываются в отслеживаемый проект. `KAT_MAC_SIGNING_IDENTITY=-` допустим только для одноразовых сборок: их нельзя устанавливать поверх основной Kat. Hardened runtime для прямой сборки выключен. Публичное распространение вне App Store без предупреждений по-прежнему требует Developer ID и нотаризации.

Перед заменой `/Applications/Kat translator.app` нужно проверить подпись и совпадение designated requirement с предыдущим выпуском, подписанным сертификатом. Одного успешного `codesign --verify` недостаточно: он принимает и ad hoc, не подтверждая преемственность. Для прямой установки нужно удалить XCTest-бандлы и подписать с `KatMac.entitlements`. Модели, настройки и история сохраняются. [Диагностика и исправление 21 октября](signing-repair-2026-10-21.md).

При переходе со старой ad-hoc сборки удалите прежние записи Kat кнопкой «минус» в «Универсальном доступе» и «Записи экрана», затем добавьте текущий `/Applications/Kat translator.app` кнопкой «плюс». Простое переключение старых записей может сохранить прежнее требование к коду. Главное окно проверяет фактическое состояние разрешений macOS и само убирает предупреждения о выданных разрешениях; устаревший переключатель не считается разрешением, и при запуске эти права не запрашиваются.

## Заметки о тестах

UI-тесты управляют приложением через XCTest; владельцу нужно один раз за сеанс подтвердить UI-автоматизацию (или заранее разрешить режим автоматизации). Запускайте тестовые сборки из DerivedData вне `~/Downloads`: иначе при запуске macOS запрашивает доступ к папке «Загрузки», и тест-раннер сообщает «hung before establishing connection». Тесты магазинной конфигурации в sandbox используют отдельные тестовые entitlements с исключением только на чтение уже скачанных моделей; opt-in помощники `testSandboxSeedModels` и `testSandboxResetContainerData` готовят и очищают контейнер sandbox.

## Локальная установка моделей (прямая сборка)

Данные прямой сборки: `~/Library/Application Support/OfflineTranslator`, вне заменяемого .app; магазинная sandbox-сборка хранит данные в собственном контейнере. Экран «Модели» позволяет импортировать уже скачанные файлы через обычную проверку контрольных сумм и установку.

На этом Mac Index 9B, полный Whisper large-v3-turbo F16, русский голос Denis, английский LJ Speech и OCR RU/EN установлены из кэшированных файлов. Whisper скопирован с подключённого телефона. Исходные пакеты занимают 7 603 355 229 байт; установленные голоса дополнительно занимают свой распакованный размер. Для этого переноса модели не скачивались.

`Tools/LocalModelImport` — явная утилита разработчика. Принимает JSON-массив с `source` (file URL), `model` (ModelDescriptor) и необязательным `package` (ModelPackage), затем каталог данных приложения. Проверка идёт той же реализацией ModelStore/PackageStore; утилита не подделывает квитанции проверки и не меняет настройки. Доказательства выполнения и точный план: `.build/macos/local-import-plan.json` и `local-import.log`.

### Корректный выход и компактная история, build 9

Убраны пояснение об отсутствии аудио и пустая строка аудио на компьютере. «Удалить» выровнено справа от действий копирования (окончательное размещение — в build 10); воспроизведение, «Поделиться» и разделитель создаются только при наличии записи. История на iPhone не менялась.

Падения при выходе через Dock в сборках 6–8 были SIGABRT из `ggml_metal_rsets_free` при статической деструкции C++: у устройства Metal оставались живые выделения модели. Теперь AppKit возвращает terminateLater, отменяет запись/воспроизведение/inference, освобождает backend «Изображения» и разговора, ставит загрузки на паузу и отвечает на запрос выхода только после выгрузки. Повторные запросы выхода объединяются. Конечное состояние AppModel не даёт отложенной работе запуска/UI снова загрузить модели. Нативные библиотеки и assertions не патчились и не обходились.

Доказательства: два runtime-теста жизненного цикла проходят (`quit-lifecycle.xcresult`); `scripts/validation/mac-quit-probe.py` запускает итоговое упакованное приложение дочерним процессом и отправляет обычный Quit через NSRunningApplication (путь как из Dock). Холодный запуск, загруженный Index и выход во время загрузки Index завершились кодом 0 за 0,286/0,236/0,755 с соответственно; в обоих сценариях с моделью unload.complete записан до выхода процесса. Трассы только с метаданными и статусы дочерних процессов: `.build/macos/quit-process-v1/report.json`. Принудительное завершение успешным тестом не считается. Регрессионная Release-сборка iOS и аудит локализации на 507 записей проходят.

Build 10 следует размеченному снимку: у записей без аудио нет нижней строки; «Удалить» стоит справа от «Копировать перевод» / «Копировать оригинал». У записей только с аудио «Удалить» остаётся рядом с «Поделиться аудио». Включает проверенное исправление выхода из build 9.

Build 10 также применяет KatTheme.accent ко всем общим кнопкам закрытия/очистки на компьютере и к иконкам главной панели инструментов. Нативные формы кнопок и неактивные состояния сохранены; элементы iPhone не менялись.

Build 9 к моменту замены был закрыт; build 10 прошёл проверки подписи и зависимостей и продолжал работать после нового запуска через Launch Services. Доказательства: `.build/macos/history-actions-installed.json`.
