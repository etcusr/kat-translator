# Следующий Apple-релиз: план оформления и публикации

[English](next-apple-release-plan.md) | **Русский**

**Прогресс, 23 октября:** [локальная подготовка 1.1.0](2026-10-22/README.ru.md): архив/экспорт iOS, прямые Mac-пакеты, тексты на четырёх языках, 24 снимка iPhone, 12 полных снимков окон Mac и 4 предпросмотра быстрой настройки, галерея README/сайта. Без загрузки и ревью. Экспорт Mac Store 79 теперь проходит с отдельным Python без TLS. Оставшиеся снимки iOS Голос/Изображение и Android, оценка iPad, демонстрация на устройстве и приёмка обновления кандидатов остаются открытыми. Пункты ниже не закрыты до выполнения всех их критериев.

Запрошено 22 октября 2026. **Это план, а не выполненная публикация.** Текущая задача не загружает сборки, не меняет App Store Connect и не отправляет на ревью. Новые публичные версии выбираются при подготовке релиза; увеличение только номера сборки не создаёт новую публичную версию.

## 1. Зафиксировать состав релиза

- [ ] Отдельно сверить изменения с последними опубликованными версиями iOS и macOS. Включить только реально выпускаемые функции и исправления каждой платформы; явно обозначить экспериментальные возможности.
- [ ] Обновить документацию репозитория и описание продукта там, где изменились поведение, возможности или ограничения. Синхронизировать живую документацию EN/RU и проверить магазинные тексты EN/RU/ES/TR.
- [ ] Выбрать новые публичные версии iOS/macOS и уникальные номера сборок; записать точный коммит исходников и проверенные пакеты.

## 2. Переделать скриншоты всех платформ и языков

- [ ] Снять окончательный интерфейс iOS/iPadOS, macOS и Android на всех поддерживаемых языках интерфейса: английском, русском, испанском и турецком. Показать режимы перевода, настройки/быструю настройку, модели и голоса там, где они доступны на платформе; не изображать ещё не реализованный паритет.
- [ ] Использовать единообразные показательные примеры и аккуратные состояния интерфейса. Исключить личные данные, идентификаторы устройств, отладочные элементы и частные записи. Проверить длинные подписи, язык, содержание переводов и особенности платформенных макетов.
- [ ] Сохранить выбранные исходные скриншоты и оптимизированные материалы в понятной директории репозитория с разбивкой по платформам/языкам и указателем. Записать версию съёмки и способ подготовки. Не добавлять избыточные тяжёлые файлы.
- [ ] Красиво представить компактную галерею на главной странице GitHub-репозитория (в обеих версиях README), со ссылками на полные наборы по платформам/языкам. Добавить те же утверждённые материалы на сайт проекта на базе GitHub.

## 3. Подготовить App Store Connect

- [ ] Заменить скриншоты iOS/macOS для каждой локализации магазина и необходимых размеров устройств, используя проверенный интерфейс релиза.
- [ ] Проверить описания и остальные метаданные; обновить по необходимости, сохранив согласованные решения по keywords/названиям, если их отдельно не пересматривают.
- [ ] Составить краткие общие патч-ноты обновления на EN/RU/ES/TR, при необходимости отметив различия платформ. Описывать итоговые изменения сборок, не выдавать планы за выпущенные функции.
- [ ] Создать/выбрать новые публичные версии iOS/macOS и загрузить проверенные сборки. Дождаться обработки и сверить выбранные номера билдов, скриншоты, метаданные и патч-ноты каждой версии.
- [ ] Проверить обновление поверх установленного приложения с сохранением моделей, голосов, настроек и истории. Отдельно фиксировать загрузку, отправку на ревью и публичный выпуск; отправлять/публиковать после поручения.

## 4. Записать короткую демонстрацию iOS

- [ ] После стабилизации интерфейса записать короткий ролик на реальном устройстве: навигация и законченный сценарий перевода. Быструю настройку/модели показывать по необходимости; исключить долгие загрузки и ожидания.
- [ ] Использовать неперсональные примеры текста/аудио. Честно показывать поведение и время работы; обозначать монтаж или ускорение, не создавая впечатление мгновенной обработки.
- [ ] Подготовить компактное видео для веба, обложку и короткие подписи. Разместить на сайте на базе GitHub и дать подходящее превью/ссылку в README репозитория; документировать расположение исходника и хостинг.

## 5. Переработать главную страницу проекта

- [ ] Сделать главную страницу GitHub Pages визуально выразительнее: логотип Kat, фирменная тёмная/графитовая основа и лаймовые акценты.
- [ ] Показать актуальные скриншоты реальных сценариев перевода и короткий воспроизводимый ролик с интерфейсом и основными функциями; связать с демонстрацией из раздела 4.
- [ ] Оставить заметными ссылки на загрузку, исходники, поддержку и политику конфиденциальности. Проверить мобильную и десктопную вёрстку, контраст, вес страницы и все поддерживаемые языки сайта.
- [ ] Приёмка: согласованный визуальный предпросмотр с логотипом, скриншотами и работающим видео, без личных данных и вводящих в заблуждение обещаний скорости; публикация — после разрешения. Пока только план, редизайн не начат.

## Подтверждение выполнения

Запись о релизе должна ссылаться на матрицу скриншотов/галерею, обновлённые описания и патч-ноты, коммит, идентификаторы загруженных сборок и статус обработки/выбора. Публикация ролика — отдельный последующий этап; готовность скриншотов или билдов не означает его завершения.
