# Git: сохранение изменений и выпусков

- После законченного изменения и подходящей проверки создавать отдельный локальный коммит с кратким описанием результата. Не накапливать несколько выпусков в незакоммиченном дереве.
- Исправления, функции и обновления документации разделять, когда изменения независимы. В описании указывать выполненную проверку и её ограничения.
- Для выпуска использовать сообщение с платформой, версией и номером сборки, например `release(ios): 0.5.6 (36) —...`. Сам коммит не означает установку или публикацию.
- Смешанное историческое состояние сохранять как snapshot, не выдумывать промежуточные версии. Снимок 12 октября 2026 включает накопленный переход в apps/shared, Android, Apple и документацию.
- Перед git add проверять список файлов, размеры, секреты, модели и артефакты. После staging повторять проверку. Сохранять исходники, каталоги/lock-файлы, небольшие поставляемые ресурсы и доказательства тестов.
- Не коммитить скачанные веса, dist, vendor/build, локальную подпись и пользовательские импорты. .gitignore не удаляет файлы с диска и не исключает уже отслеживаемые файлы автоматически.
- Не применять reset/clean и не переписывать историю для экономии места без отдельного поручения. Игнорируемые веса и сборки не защищены Git; для них нужна отдельная резервная копия.
- Push/публикация выполняются по соответствующему поручению; локальный коммит не является внешней резервной копией.

## Публичная история

Работать из корня текущего проекта: `main` → `origin/main` репозитория `etcusr/kat-translator`. Публичная история начата заново 14.10.2026 с коммита `Initial source import`; прежние коммиты в новый репозиторий не отправлены. Код опубликован под GPL-3.0-or-later. Локальные резервные архивы прежней истории не включать в Git, не сливать старые ветки и не выполнять `push --mirror`. Новые изменения сохранять отдельными краткими коммитами. Публикация исходников не означает разрешение на все последующие push.

## Публичные изменения

Сообщение коммита кратко описывает добавленное, исправленное или удалённое. История обсуждений, служебные инструкции и журналы ассистентов в Git не включаются. Документация описывает продукт, сборку, проверки и ограничения. Обновлять CURRENT_STATE, ARCHITECTURE и затронутые инструкции при изменении реализации.
