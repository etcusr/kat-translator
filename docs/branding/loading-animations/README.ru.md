## Английская подпись cat-break — 14 октября 2026

Ролик `cat-break` и его постер теперь содержат **CAT BREAK** вместо двух русских подписей. Он общий для всех языков iOS/macOS/Android; фильтра по языку нет. H.264 384×288, 24 fps, 103 кадра / 4,292 секунды, без звука. Чёрные полосы закрывают прежние подписи, центральная область сохраняет движение кота.

`prepare-loading-animations.py` автоматически применяет `localize-cat-break.py` после нормализации этого ролика. Локализатор использует ffmpeg и macOS AppKit (`render-cat-break-caption.swift`) для воспроизводимого текстового слоя; исходник должен иметь размер 384×288. Постер снимается из нового видео. Исходные SHA в каталоге относятся к первоначальным роликам; преобразование отмечено полями `caption`/`captionLanguage`. Изменение надписи не меняет происхождение и права на исходный клип.

Актуальные галерея и ZIP обновлены; отдельное GIF-превью: `dist/share/loading-cat-break-en.gif`. Установленные/ранее загруженные приложения получат замену после обновления сборки.

## Постоянная галерея — 11 октября 2026

Текущий набор: 10 движений кота и 13 роликов. 14 октября `one-beer` удалён из ресурсов всех платформ и генератора; старые подписанные пакеты остаются историческими артефактами. Добавлен трюк с лужицей и прыжком через неё; «Кучка» теперь заканчивается закапыванием задними лапами. Оба сценария входят в последовательное воспроизведение. Отскок начинается заранее и включает толчок, подбирание лап и мягкое приземление. Перед лужицей видны три коротких сокращения корпуса; закапывание сохранено. Позже ещё один ролик удалён из ресурсов всех платформ и генератора.

[Открыть галерею](gallery/index.html). Здесь находятся **только актуальные** движения нарисованного кота и ролики приложения. Кнопка **«Воспроизвести всё»** запускает их по очереди, показывает текущий номер и останавливает просмотр при повторном нажатии. Отдельные карточки тоже можно воспроизводить и скачивать. HTML работает после распаковки всей папки без сервера и интернета.

**Правило дальнейшей работы:** добавление, изменение или удаление анимации всегда сопровождается обновлением этой галереи. Исторические экспорты в `dist/share/*-2026-10-11` остаются снимками; поддерживаемый каталог — `gallery/`.

```bash
python3 scripts/update-animation-gallery.py          # обновить текущую галерею
python3 scripts/update-animation-gallery.py --zip    # также архив для отправки друзьям
python3 scripts/update-animation-gallery.py --check  # только проверка актуальности
```

Источник списка роликов — `assets/bundled/LoadingAnimations/loading-animations.json`; новые элементы автоматически получают карточку, удалённые исчезают из HTML и управляемых файлов. Можно указать `title` в записи манифеста для подписи нового ролика. Экспорт кота использует текущие SwiftUI-рисунок, модели движения, `CatLoadingPlay.Trick.allCases` и форму из приложения. Новые случайные трюки автоматически попадают в экспорт; если для трюка нужен особый запуск, экспорт явно остановится до обновления сценария, а не пропустит его незаметно.

Изменение исходников кота инвалидирует экспорт: следующий запуск перерисует MP4/GIF/постеры через SwiftUI и ffmpeg. При неизменном коде тяжёлый экспорт повторно не выполняется. `--check` не требует ffmpeg или компиляции. HTML/CSS/JS генерируются из `scripts/update-animation-gallery.py` и `scripts/animation-gallery/`; вручную менять файлы в `gallery/` не нужно.

Подготовка новых роликов автоматически обновляет галерею. Генераторы iOS/macOS-проектов и упаковка Mac проверяют её актуальность до записи проекта/сборки пакета. Синхронизация удаляет только файлы из собственного `_generated.json`, сохраняя любые сторонние заметки. Регрессии добавления/удаления/границ папки: `python3 scripts/validation/test_animation_gallery.py`.

Текущий архив для друзей: `dist/share/Kat-loading-animations-current.zip`. Он содержит всю папку с HTML и медиа; для просмотра достаточно распаковать и открыть `index.html`. Перекодирование роликов приложения для галереи не выполняется.

## Ролики обработки — исходная интеграция

Пользователь предоставил Telegram-ролики MP4 (изначально 15, после удаления двух роликов 14 октября — 13). Они вместе с существующим котом-волшебником образуют общий локальный плейлист **только в прежних местах CatWizardView** при обработке голоса/текста. Коты подготовки модели и прогресса загрузки не изменились.

- Ролики перемешиваются без повторов; нет подряд идущего повтора между циклами перемешивания или отдельными ожиданиями в одном процессе приложения.
- Выбор ролика переживает обновления тела SwiftUI. Начиная с Mac 29 / iPhone 18 каждый ролик проигрывается один раз, затем плейлист переходит к следующему по окончании. Короткие ролики больше не повторяются ради заполнения 8 секунд. Завершение/отмена сразу убирает анимацию.
- Один беззвучный AVPlayer и один текущий элемент на видимую поверхность; аудиосессия не меняется. Воспроизведение ставится на паузу, когда приложение неактивно или включено «Уменьшение движения»; постер остаётся видимым. При разборке удаляются наблюдатель и элемент плеера.
- Встроенный H.264 384×288, aspect-fit с чёрными полями, частота кадров не выше 24 fps, весь звук удалён. Исходные идентификаторы хранятся в манифесте; сырые исходные файлы в репозитории не распространяются.
- `scripts/prepare-loading-animations.py` воспроизводит ресурсы с помощью ffmpeg/ffprobe. `assets/bundled/LoadingAnimations/loading-animations.json` хранит исходные имена, SHA-256, размеры результатов и длительности. Суммарный размер видео на момент интеграции: 1 628 520 байт; JPEG-постеры дополнительно.

## Центральный оверлей обработки (Mac 29 / iPhone 18)

Распознавание голоса/импорт аудио и перевод текста показывают одну крупную анимацию в общем оверлее над затемнённой рабочей областью. Ширина подстраивается под доступное место, до 640 pt, с сохранением холста 4:3. Статус, необязательный реальный прогресс по частям/символам и кнопка «Отмена» не меньше 44 pt остаются видимыми. Рабочая область под оверлеем отключена и скрыта от средств доступности на время обработки. Отмена использует существующий путь отмены конвейера; редактирование с клавиатуры завершается при появлении оверлея.

Оверлей исчезает при завершении обработки или начале озвучки, поэтому при автоозвучивании результат остаётся читаемым. Он не используется при подготовке/загрузке моделей, в «Изображении» и во время записи с микрофона. Существующие маленькие индикаторы подготовки речи остаются. По просьбе пользователя короткие ролики теперь проигрываются один раз перед выбором следующего.

Проверка: нативный UI-тест Mac прошёл (25,868 с), включая центральную «Отмену», отмену, последующее реальное редактирование текста, перезапуск и результат перевода. Нативный UI-тест iPhone прошёл (50,381 с), включая размер оверлея/зону отмены, отмену/перезапуск и возврат к результатам. Тест видимости автовоспроизведения на Mac прошёл (1,524 с). Итоговые тесты плейлиста: 4 прошли, 0 ошибок (6,940 с), включая реальный переход после первого проигрывания и нативную передачу постер/видео. Снимки на обоих устройствах просмотрены. Доказательства: `.build/processing-overlay/`. Первая попытка UI-теста на Mac упала из-за ненадёжного флага доступности NSTextView; проверка реального редактирования заменила это условие и прошла.

- Оба пакета: все 15 роликов того времени и постеры проверены по нормализованным ресурсам; подписи прошли.
- DMG Mac: контрольная сумма проверена; аудит зависимостей не нашёл внешних несистемных библиотек среди 86 Mach-O.
