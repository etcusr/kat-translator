# Статический аудит iOS-кода — 22 октября 2026

Сверено с `main` на `97aef9d` (iOS 1.0.1 (67) в исходниках). Аудит **только по чтению кода**: ничего не собиралось и не запускалось, на iPhone не проверялось, код не менялся. Пометки:

- **подтверждено** — путь прослежен по коду, проявление следует из написанного;

## 1. Потеря пользовательских данных (приоритет)

**P1. Автоблокировка или уход в фон уничтожают запись и идущий перевод** — подтверждено.
`OfflineTranslatorApp.swift:32-34` → `AppModel.background()` (`AppModel.swift:546`) → `cancel()` (`:520`: `recorder.cancel(); session.cancel()`). `isIdleTimerDisabled` в рабочем коде не выставляется (только в пробах). Монолог в режиме переключения без касаний → экран гаснет → запись потеряна.
Исправление: `isIdleTimerDisabled = true` на время записи/распознавания/перевода; при `.background` завершать запись (`finishRecording`) и сохранять аудио; GPU-инференс в фоне останавливать, но вход сохранять для повтора.

**P2. Звонок, Siri, подключение/отключение наушников обнуляют запись** — подтверждено.
`AudioRecorder.swift:135-151`: на `interruption began`, `oldDeviceUnavailable`, `newDeviceAvailable`, `noSuitableRouteForCategory` → `cancel()`; уже записанные сэмплы не финализируются. Противоречит контракту «сохранность полного исходного аудио».
Дополнительно `AppModel.swift:138-146` на `oldDeviceUnavailable` вызывает общий `cancel()` — отключение AirPods прерывает идущий перевод 9B, хотя ему звук не нужен.
Исправление: при прерывании — остановка с финализацией (как `onLimit`), отмена только если ничего не записано; на смену маршрута — останавливать лишь воспроизведение.

**P3. «Отменить всё» удаляет модели, докачанные давно** — подтверждено.
`DownloadBatch` очищается только в `defer` очереди при полном успехе (`PackageDownloadCoordinator.swift:459-463`) или в самой отмене (`:597`). Пауза группы, досрочный `return`, докачка кнопкой в строке оставляют id в группе. `cancelCurrentBatch` (`:561-581`) безусловно делает `item.store.remove(item.model)`. Сценарий: пауза группы → 9B докачан из строки → через дни «Отменить всё» → 5,8 ГБ удалены, хотя диалог обещает сохранить установленное.
Исправление: исключать из группы id, ставшие установленными любым путём; показывать кнопку только при активных/частичных элементах; в `cancelCurrentBatch` не удалять полностью установленные.

**P4. Нечитаемый `history.json` блокирует историю навсегда** — подтверждено.
`TranslationHistory.swift:77-78`: любая ошибка чтения → `HistoryError.corrupt`; `loaded` остаётся `false`, все операции бросают ошибку; `removeAll()` (`:265`) сначала вызывает `load()`, поэтому «Очистить» тоже не работает. `HistoryEntry.Kind` (`:20`) без запасного значения: установка более старой сборки поверх новой с новым типом записи ломает декодирование всего массива. Ошибка чтения при `.completeFileProtection` на заблокированном устройстве тоже трактуется как повреждение.
Исправление: при ошибке декодирования переименовать файл в `history.corrupt-<дата>.json` и начать с пустого; декодировать записи по одной; `removeAll` без декодирования; различать ошибку доступа и повреждение.

**P5. Длинная озвучка не сохраняется в историю и «Поделиться»** — подтверждено.
Потоковая озвучка склеивает все предложения в один буфер (`ConversationPipeline.swift:939`: `pcm += prepared.pcm.samples`), затем пишет одним вызовом (`:526`, `speak()` → `shareCache.append` `:567`). Оба приёмника отклоняют куски длиннее 60 с (`TranslationHistory.swift:227`, `TextSpeechShareCache.swift:91`). При ошибке `:527` — `abortAudio`, `lastHistoryID = nil`, «Озвучка не сохранена». Порог — примерно от 800 символов русского перевода; для Index 2B потоковый путь используется всегда.
Исправление: хранить PCM потоковых предложений отдельными кусками и дописывать по одному.

**P6. Предупреждение о памяти во время записи без предпросмотра отменяет запись** — подтверждено.
`AppModel.swift:560-567`: ранний выход только при `session.isRecordingPreview`; иначе при `relieveMemoryPressure() == false` → `unload()` → `cancel()` → `recorder.cancel()`.
Исправление: во время записи выгружать модели, не трогая рекордер. Там же: сообщение «Модели выгружены…» показывается, даже если ничего не было загружено (`ConversationPipeline.swift:755-756`).

## 2. Средний приоритет

**M1. Срок хранения истории применяется по промежуточному значению ползунка** — подтверждено.
`SettingsView.swift:177` пишет `@AppStorage` непрерывно; `HistoryModel.refresh()` (`:36-39`) вызывает `setPolicy` с очисткой на каждой активации сцены (`OfflineTranslatorApp.swift:37`), в том числе при открытых настройках. Провести ползунок через «1 день» и потянуть Пункт управления → тексты старше суток удалены. Нарушает правило «очистка только при закрытии настроек». Исправление: снимок политики при открытии, применение только в `saveRetention`.

**M2. «Авто» на мощном устройстве игнорирует OPUS** — подтверждено.
`OpusDirectionRoutes.swift:49`: `strongDevice ? [.index9B, .index2B] : [...]`. Без установленного Index при наличии OPUS для пары — `modelLanguageUnavailable` (`PackageDownloadCoordinator.swift:84-85`), причём уже после распознавания. Исправление: OPUS как запасной вариант в конце списка.

**M3. Пиковая память при смене модели в «Авто»; нет проверки памяти перед Index** — на устройстве.
`prepare()` (`ConversationPipeline.swift:234-238`) выгружает ASR перед загрузкой MT, но `run()` (`:408` → `:442`) и путь предпросмотра (`:838-839`) грузят новую модель при загруженном Whisper. `LlamaTranslationBackend.swift:43` → `ot_mt_load` без `os_proc_available_memory()`, хотя `OmniVoiceSynthesis.swift:13` такую проверку имеет. Риск jetsam на 8-ГБ iPhone, особенно при ручном выборе 9B.

**M4. Выбор модели «Авто» выполняется до проверки пустой речи** — подтверждено.
`run()`: `resolveTranslation` (`:408`) → `supports` (`:410`) → `guard !sourceText.isEmpty` (`:412`) → сохранение оригинала (`:413-417`). Тишина выгружает прогретую модель; при ошибке выбора распознанная запись не попадает в историю.

**M5. Окно предпросмотра растёт без ограничения** — подтверждено по коду, нагрузка на устройстве.
`RecordingPreview.swift:197, 226-228`: начало окна сдвигается только после подтверждённого блока. Без точки от Whisper или при переформулировке короткого контекста (`:119`) каждая пауза заново распознаёт всё с последнего подтверждения (до 30 мин), каждый снимок копирует до 115 МБ. Нужен жёсткий предел окна или откат к обработке после остановки.

**M6. После отмены работа продолжается вне отслеживания** — путь подтверждён.
Финальный `process(...)` в `RecordingPreviewCoordinator.finish()` (`RecordingPreview.swift:92-95`) идёт вне `job`, `waitForIdle()` (`:86`) его не ждёт; `cancel()` сбрасывает `isBusy` (`ConversationPipeline.swift:733-735`) раньше. `defer` в `run` отменяет `streamedStart` (`:359`), но не ждёт; поздний `voiceLoaded = target` (`:470`) может попасть в новую операцию. Native-очереди предотвращают порчу памяти, но флаги `asrLoaded/mtLoaded/voiceLoaded/files` меняются задним числом.

**M7. Рекордер: малый запас и обрезка хвоста** — на устройстве / подтверждено.
`AudioRecorder.swift:6, 28-31`: очередь конвертации без QoS, запас 8 буферов (≈340 мс при 48 кГц), превышение → ошибка всей записи. При параллельных Whisper (предпросмотр) и MT на `.userInitiated` это реально. `AudioQueueCapture.swift:78-81`: `AudioQueueStop(queue, true)` немедленно, поздние буферы отбрасываются → обрезан конец последнего слова. Исправление: `qos: .userInteractive`, допуск в секундах аудио; `AudioQueueStop(queue, false)`/`AudioQueueFlush` с приёмом буферов до завершения.

**M8. Загрузки.**
- Пауза в момент завершения (`ModelDownloader.swift:149` ставит `.restartRequired` до `cancel(byProducingResumeData:)`; колбэк `:264` выходит без проверки и без удаления) оставляет готовый `staging-N.bin` сиротой; повторная загрузка — на устройстве.
- Resume data, пришедшие при перезапуске после убийства процесса, отбрасываются, если `restore()` успел поставить `.restartRequired` (`:101-102`, `:282`) — на устройстве.
- Обработчик завершения фоновой сессии вызывается после полной SHA (до 5,8 ГБ), распаковки и сборки пакетов (`:306-313`) — риск завершения системой — на устройстве.
- Любое истечение `BGContinuedProcessingTask` ставит все загрузки на паузу (`DownloadLiveActivity.swift:24`, `DownloadContinuedTask.swift:69-78`), включая системное.
- Сборка OPUS-направления (`OpusDirectionPackages.swift:389-393`) не вызывает `DownloadLiveActivity.changed()` и не держит `DownloadBackgroundWork` (в `OpusPackage.swift:296-297` есть) — системная задача может не завершиться.
- Проверка места требует `byteCount * 2 + 256 МБ` (`ModelDownloader.swift:110`, `PackageDownloadCoordinator.swift:492`) при загрузке переименованием: для 9B — 11,8 ГБ вместо ~6.
- Каталоги `staging-UUID`/`piper-UUID` (`PackageStore.swift:69-70, 87-88, 120-122`) и старые `staging-N.bin` после убийства процесса никогда не удаляются.
- `ModelStore.swift:90`: любая ошибка проверки при запуске удаляет квитанцию → повторная загрузка рабочей модели.
- `cancelCurrentBatch` → `pauseAll()` ставит на паузу и загрузки вне группы; отмена в строке отменяет очередь группы.
- `isExcludedFromBackup` ставится на корень данных, когда `transferRoot == root` (`ModelDownloader.swift:44, 51`; legacy F16 на iOS, всегда на Mac) — история исключается из резервной копии.
- Live Activity: берётся только `.activities.first` (`DownloadLiveActivity.swift:142, 178`), старые не закрываются.

**M9. Камера не восстанавливается после ошибки сессии** — подтверждено отсутствие обработки (уточнено).
В `apps/ios` и `shared/apple` нет подписки на `AVCaptureSession.runtimeErrorNotification` и `AVAudioSession.mediaServicesWereResetNotification`. Обычные прерывания (звонок и т. п.) `AVCaptureSession` снимает сама, а при уходе в фон камера закрывается (`CameraView.swift:128-130`), поэтому они не проблема. После runtime-ошибки или сброса медиасервисов `CameraModel` остаётся `active`, а `CameraCapture.start()` (`:32-86`, защёлка `configured`) вызывается только при открытии/«Ещё фото» — превью чёрное до закрытия и повторного открытия камеры. Приоритет — низкий/средний.

**M10. Тест устройства сохраняет неверный класс** — подтверждено по коду.
`DeviceProbe.swift:47-52`: при неудаче GPU-прохода (`gpu = -1`, например приложение свернули) сохраняется оценка только по CPU — мощный iPhone навсегда «слабый», «Авто» выбирает OPUS/2B. `DeviceProbe.c:136`: не проверяется результат `pthread_create`, затем `pthread_join` по неинициализированному дескриптору.

**M11. `RecordingPreviewProbe.swift` компилируется в магазинную сборку** — подтверждено.
`generate-project.py` включает всё из `apps/ios`; файл без `#if`, вызывается из `AppModel.swift:182-193` по переменной окружения. Содержит force unwrap (`:48`), запись в Documents, управление автоблокировкой. Остальные пробы закрыты флагами — этот тоже стоит закрыть `#if RECORDING_PREVIEW_PROBE`.

**M12. Гонки, скрытые `@unchecked Sendable`** — на устройстве.
`LlamaTranslationBackend.swift:63` читает `model` вне очереди (пишется на очереди `:40`); `OpusTranslationBackend.swift:43-47` — `directionsRoot` (пишется `:25, :32`); `OmnilingualBackend.swift:9-22` — `useCoreML/useOmni`. При пересечении смены модели «Авто» с запросом проверка языка/маршрута идёт по старому значению.

## 4. Оптимизации (по ожидаемой пользе)

1. **Перерисовки корневого экрана.** `ConversationView` наблюдает `model/session/recorder/packages/history` (`ConversationView.swift:17-21`). Весь экран пересчитывается: 10 раз в секунду от `recorder.elapsed` (`AudioRecorder.swift:259-264`, показ — целые секунды); на каждый `didWriteData` (`ModelDownloader.swift:241-245` → `PackageDownloadCoordinator.swift:282`); на каждый partial перевода; на каждый кадр скролла (`voiceReadingScroll`, `:511-515`). Вынести таймер/прогресс в подвью, публиковать секунды при смене, ограничить прогресс загрузок ~4 Гц, не наблюдать `history` в корне.
2. **Полная перепроверка SHA после каждого обновления.** `VerifiedFileStamp` включает ctime (`FileVerificationCache.swift:26-27`); отчёт о загрузках 22.10 фиксирует изменение только ctime у квитанций. Восстановление последовательное (`PackageDownloadCoordinator.swift:310-317`), «Проверяю модели…» блокирует работу. Хранить inode+размер+mtime или проверять в фоне без блокировки.
3. **Определение языка текста на главном потоке** при каждой перерисовке (`ConversationView.swift:97-99, 435, 437`), первая загрузка `lid.176.ftz` тоже там. Дебаунс через `.task(id:)` и кэш.
4. **Задержка до первого результата.** Прогрев после загрузки (компиляция Metal-шейдеров ggml на первом запросе) для Index и Whisper; AAC-кодирование и сохранение оригинала (`ConversationPipeline.swift:361-367, 413-417`) параллельно с ASR; явный `flash_attn` у Whisper (`WhisperBackend.swift:37-38`, проверить значение по умолчанию в зафиксированной версии); замер `n_ubatch` 256/512 вместо 128 (`TranslationRuntime.cpp:126`) с контролем памяти; одна категория аудиосессии вместо переключения дважды за ход (`AudioRecorder.swift:183, 325`, `SpeechPlayer.swift:95`); кэш сессии Silero VAD (`AudioRecorder.swift:175`).
5. **Загрузки и хранение.** Одна фоновая `URLSession` с ключом в `taskDescription` вместо сессии на файл (`ModelDownloader.swift:59-64`); хэширование буфером 8–16 МиБ с `F_NOCACHE` вместо `read(upToCount: 1 MiB)`; не хэшировать части пакетов повторно (`PackageStore.swift:97-107`); удалять `.tar.bz2` голосов после распаковки (67–292 МБ на голос).
6. **История.** Индекс переписывается 4–5 раз за перевод и при каждой активации (`TranslationHistory.swift:188, 219, 251, 254`) — писать только при изменении. Миниатюры грузят полный PNG через актор (`HistoryImageView.swift` → `TranslationHistory.swift:140`) — `CGImageSource` с уменьшением и `NSCache`.
7. **Горячие циклы.** `try! NSRegularExpression` на каждый вызов `words()` (`RecordingPreview.swift:100`) — статический; `unpublished(previousTranscript)` в цикле (`:161`) — вынести; обработка partial каждые 60 мс по всей строке (`ConversationPipeline.swift:899`) — с последнего смещения; `RecordingReconciliation` O(blocks×sentences) на главном акторе.
8. **Whisper на длинных записях.** `temperature_inc = 0` (`WhisperBackend.swift:64`) отключает откат температуры против зацикливаний; подавать VAD-сегменты (`SpeechActivityDetector` уже есть).
9. **Прочее.** `ResourceMonitor.sample()` каждые 250 мс во время записи считает 8 значений при использовании двух; `L10n.text` ищет бандл и читает UserDefaults на каждый вызов; двойной `history.refresh()` при запуске; анимация кота 30 к/с во время загрузки модели.
10. **Сборка.** `generate-project.py` не задаёт `SWIFT_COMPILATION_MODE` — проверить, что Release собирается `wholemodule`. Swift 5 + `SWIFT_STRICT_CONCURRENCY=targeted` при многих `@unchecked Sendable` скрывает гонки M12; поэтапный переход к `complete` начать с `OfflineCore`.

## 5. Архитектура и сопровождение

- `ConversationPipeline` (~950 строк, `run()` ~215) и `AppModel`: шаблон «`isBusy` + `generation` + `active` + `defer`» повторён в 8 точках с расходящимися `defer` (источник M6 и «Останавливаю…»); около 12 флагов занятости, их проверки скопированы во view (`ConversationView.swift:71-91`, `VoiceStageControls.swift:24-26`). Предложение: один сериализованный исполнитель операций и одно перечисление состояния взаимодействия.
- Подготовка TTS («загрузить голос → `SpeechPreparation` → собрать PCM») продублирована трижды; последовательность выгрузки ASR — около 10 раз (в двух местах не сбрасывается `loadedASRURL`); `PipelineFiles` пересобирается вручную в 4 местах — нужен `with(...)`.
- Семь типов флагов отмены с разной семантикой; лимиты (1536, 480, 65 536, 16 384) продублированы в Swift и C++; коды возврата — голые числа. Свести в общий C-заголовок.
- Сборка пакетов OPUS и OPUS-направлений скопирована и уже разошлась (M8); ожидания реализованы циклами `sleep` 20–200 мс; `restore()` при раннем выходе не гарантирует завершения для вызывающего.
- Ключи настроек и значения по умолчанию разбросаны (`automaticSpeechVoice` — 3 места, сроки истории — 2) — один тип настроек.
- Отличие iOS/Mac: на iOS 2B и 9B делят один контекст Llama (`RoutedTranslationBackend.swift:161`), на Mac — разные экземпляры; не задокументировано.
- Скрытый legacy-загрузчик Whisper F16 на iOS (`OfflineTranslatorApp.swift:11`) может установить ~1,6 ГБ, которые не видны в UI и не удаляются.

## 6. Экран камеры (дочитан 22.10 после первой версии)

Файлы: `apps/ios/Camera/CameraModel.swift`, `CameraView.swift`, `CameraOverlay.swift` (+ ранее `CameraCapture.swift`). Проверено и защищено: кадры для OCR прореживаются (не чаще ~3 в секунду, `CameraCapture.swift:149`) и уменьшаются до 1600 px; одна доставка кадра за раз (`delivering`); снимок и импорт декодируются с ограничением 3072 px вне главного потока (`CameraOverlay.decode`, `Task.detached`); устаревшие OCR-результаты отбрасываются по `generation/scene` и сигнатуре кадра; временный файл «Поделиться» удаляется (`CameraView.swift:250`); закрытие камеры дожидается OCR, перевода и архивации.

**C1. Кодирование PNG снимка на главном потоке; большой PNG в истории** — подтверждено (производительность).
`CameraModel` — `@MainActor`. `archiveResultIfNeeded()` (`CameraModel.swift:165-174`) после каждого готового перевода снимка делает `CameraOverlay.composite(...)` и `.pngData()` для изображения до 3072 px по длинной стороне — на главном потоке; то же в `savePicture`/`sharePicture` (`:175-192`). Ожидаемый подвис интерфейса — сотни миллисекунд (на устройстве), а запись истории — PNG фотографии порядка 10+ МБ. Исправление: композитинг и кодирование в фоне; для истории и «Поделиться» — HEIC/JPEG.

**C2. Отрисовка оверлея перевода на главном потоке** — подтверждено (производительность).
`translation.$translated` → `CameraOverlay.render` (`CameraModel.swift:59-62`, `CameraOverlay.swift:7-23`) на каждое обновление блоков: полный растр размера кадра (до 3072 px, ~28 МБ) и линейный подбор шрифта с шагом 0,5 (до ~58 вызовов `boundingRect` на блок). На снимке с десятками блоков — тысячи измерений текста на главном потоке при каждом обновлении. Исправление: двоичный поиск размера шрифта, отрисовка вне главного потока или только изменившихся блоков.

**C3. Сигнатура кадра на главном потоке** — подтверждено, низкий.
`receive` (`CameraModel.swift:95`) и проверка результата OCR (`:112`) рисуют кадр 1600 px в 16×16 на главном акторе — дважды на кадр. Считать в `CameraCapture` на очереди кадров и передавать вместе с изображением.

**C4. Тупик при ошибке подготовки перевода** — подтверждено, низкий.
`open()` (`CameraModel.swift:82-89`): `active = true`, а при неудачном `translation.prepare` (`translation.ready == false`) выходит без запуска камеры и без сброса `active`. Ошибка показывается, но «Снять» и «Галерея» заблокированы (`canCapture`, `!translation.ready`), повторный `open()` отсекается `guard !active`. Выход — только закрыть и открыть камеру. Исправление: при неудаче сбрасывать `active` или показывать кнопку повтора.

**C5. Импорт больших изображений** — низкий.
`CameraOverlay.decode` отклоняет данные больше 50 МБ общей ошибкой `CameraError.image` (`CameraOverlay.swift:32`); `PhotosPicker` грузит полный `Data` (`CameraView.swift:126`). Для панорам/ProRAW — непонятное сообщение. Нужен отдельный текст ошибки или загрузка через файл/`CGImageSourceCreateWithURL`.

**C6. Перерисовки экрана камеры** — оптимизация.
`CameraView` наблюдает `AppModel`, `PackageDownloadCoordinator`, `ImageTranslationSession` и `CameraModel`, который сам пересылает `objectWillChange` перевода (`CameraModel.swift:55`) — двойная инвалидация; экран пересчитывается на каждый чанк загрузки (см. п. 4.1). `model.status` (`:67-77`) при каждом пересчёте заново проверяет поддержку языков моделью (см. п. 4.7, `OpusDirectionRoutes.languages`).

1. P1–P6 отдельными небольшими коммитами; для P3–P5 и M1, M2, M4 — unit-тесты в `OfflineCore` (логика группы, декодирование истории, порог 60 с, порядок «Авто»).

4. Рефакторинг конвейера в единый исполнитель операций — после покрытия тестами.

Каждое изменение проверять отдельно: сборка, unit-тесты, устройство, качество — согласно `docs/GIT_WORKFLOW.md`.
