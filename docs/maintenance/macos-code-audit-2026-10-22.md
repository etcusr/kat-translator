# Статический аудит macOS-кода — 22 октября 2026

Сверено с `main` на `f6e19af` (Mac 0.6.9 (62) в исходниках). Аудит **только по чтению кода**: ничего не собиралось, не запускалось и на Mac не проверялось. Пометки:

- **подтверждено** — путь прослежен по коду;
- **на Mac** — путь в коде есть, проявление нужно воспроизвести на компьютере.

Охват: `apps/macos/*` (Swift, Info.plist, entitlements, `InfoPlist.strings`, `project.pbxproj`), ветки `#if os(macOS)` в `shared/apple` и `OfflineCore`, `shared/native/IndexMLX`, `shared/native/OpusGPU`, `shared/native/app/Translation/MLXRuntime.c`, скрипты сборки/подписи/упаковки (`generate-macos-project.py`, `bundle-macos-runtimes.py`, `build-macos-runtimes.sh`, `build-macos15-26.sh`, `prepare-macos15-runtime.py`, `build-opus-runtime.sh`, `package-macos.sh`, `archive-macos-appstore.sh`, `mac-signing.py`, `sign-verified-speech-sdks.py`, `check-macos-bundle.py`). Не смотрелись: `Dependencies/`, vendor (MLX, omlx/MTP, llama.cpp, whisper.cpp, CTranslate2), Python-окружения, скрипты вне перечня (`install-sdk-privacy-manifests.py`, `prepare-index-mlx.py`, `prepare-opus-gpu.py`, `build-identity.py`). Общий код iOS/macOS уже разобран в [ios-code-audit-2026-10-22.md](ios-code-audit-2026-10-22.md); раздел 6 ниже перечисляет, что оттуда относится к Mac.

**Уточнение архитектуры.** Index 9B на Mac работает не в отдельном процессе, а во **встроенном CPython внутри процесса приложения** (`MLXRuntime.c:39-47`: `ot_wayu_python_init` + `PyImport_ImportModule("index_mlx")`), с общим `sys.path` с фронтендом Wayu (`WayuFrontend.c`). Отдельный процесс — только OPUS GPU (`opus_gpu.py`). Формулировку «Mac Python workers» в `CLAUDE_HANDOFF.md` (раздел 3) стоит поправить.

Проверено и признано защищённым: объединение повторных Quit и единственный ответ `reply(toApplicationShouldTerminate:)`; OPUS-воркер завершается по EOF stdin при смерти приложения, stderr не через pipe (нет взаимоблокировки), окружение изолировано (`-S -B`, `PYTHONNOUSERSITE`, isolated `PyConfig`), JSON-кадрирование с лимитом 1 МБ, строгий запрос-ответ и закрытие воркера на любой ошибке/отмене (нет устаревших результатов); отмена MLX через атомарный флаг на каждом шаге генерации, `gen.close()` в `finally`, удержание неполного UTF-8; сериализация выгрузки и инференса (`RetainedTranslationBackend` + очереди); Carbon-хоткеи (снятие регистрации перед повторной, ошибки показываются); локальные `NSEvent`-мониторы снимаются; чтение выделения проверяет `IsSecureEventInputEnabled` и `AXSecureTextField`, буфер обмена восстанавливается только если `changeCount` не сдвинулся; обработчик Services только ставит работу в очередь; геометрия захвата области (перевёрнутый view, масштаб на каждый дисплей, исключение собственного оверлея); импорт изображений ограничен 50 МБ/3072 px; `set -euo pipefail` и кавычки во всех `.sh`; порядок подписи изнутри наружу без `--deep`; `.pyc` не пишутся в подписанный бандл; закреплённые SHA в `fetch-speech-runtime`/`prepare-mac-glossary`; `mac-signing.py` не откатывается молча на ad hoc; проверки архива App Store; entitlements помощника (`app-sandbox` + `inherit`).

## 1. Высокий приоритет

**X1. Глобальные хоткеи по умолчанию ⌥1/⌥2/⌥3, вероятно, не регистрируются** — на Mac (проверка: нажать ⌥1).
`MacShortcuts.swift:94-96`: `MacShortcut(keyCode: 18, modifiers: .option, …)` для выделенного текста, области экрана и буфера. С macOS 15 `RegisterEventHotKey` отказывает сочетаниям только с ⌥ или ⌥⇧; ошибка уходит в «Сочетание занято другим приложением…» (`MacGlobalHotkeys.swift:46-48`), а валидатор (`MacShortcuts.swift:136-138`) такие сочетания разрешает. Если регистрация всё же проходит, ⌥+цифра на многих раскладках печатает символы (на британской ⌥3 = «#», ⌥2 = «€») — хоткей отнимает их у всей системы. Ручная приёмка хоткеев в документах не зафиксирована. Исправление: по умолчанию ⌃⌥1/2/3; в валидаторе запретить для глобальных действий только ⌥ и ⌥⇧.

**X2. Запись на Mac не переживает смену устройства ввода** — подтверждено.
В `AudioRecorder.swift` (ветка macOS, `AVAudioEngine`) нет подписки на `AVAudioEngineConfigurationChange` (есть только в `SpeechPlayer.swift:79`). При подключении AirPods, переключении профиля или отключении USB-микрофона движок останавливается, таймер продолжает «записывать», звук больше не поступает — сказанное теряется или приходит «речь не найдена». Исправление: при смене конфигурации завершать запись с сохранением уже записанного (или перезапускать вход).

**X3. Прямой DMG/ZIP не нотаризуется и не открывается на чужих Mac** — подтверждено (актуально, если пакет раздаётся кому-то ещё).
`project.pbxproj:506, 508`: `ENABLE_HARDENED_RUNTIME = "NO"`; `package-macos.sh:29` и `bundle-macos-runtimes.py:143-145` подписывают без `--options runtime` и `--timestamp`; `notarytool`/`stapler` нигде нет; `mac-signing.py` принимает сертификат Apple Development. На macOS 15+ скачанная копия блокируется Gatekeeper, обход через Control-клик убран. Для раздачи нужен Developer ID, hardened runtime на приложении и вложенных исполняемых (`OpusPython`, `torch_shm_manager`), `--timestamp` на каждом Mach-O, `notarytool submit --wait` и `stapler` для приложения и DMG. Для тестовых сборок с hardened runtime понадобится Debug-only `disable-library-validation`.

**X4. Сбой MLX/Metal роняет всё приложение** — на Mac.
Index 9B (~5,2 ГБ) генерирует в процессе приложения. Ошибки командного буфера Metal (например, нехватка памяти) в MLX завершаются `std::terminate`. На 16-ГБ Mac с 9B, Whisper и OCR одновременно — падение приложения с потерей текущего хода. OPUS GPU вынесен в отдельный процесс и такой сбой изолирует; для 9B стоит рассмотреть то же или хотя бы ограничить кэш MLX (см. п. 4).

**X5. Современная сборка берёт Python из Homebrew** — подтверждено.
`bundle-macos-runtimes.py:22`: `py=Path('/opt/homebrew/opt/python@3.11/...')` — stdlib, `lib-dynload`, `libpython`, помощник `OpusPython` и зависимости Homebrew (openssl, xz, sqlite, mpdecimal) попадают в бандл из того, что установлено на машине сборки; то же в `build-macos-runtimes.sh:28, 33` и путь заголовков в `generate-macos-project.py:51` (абсолютный `/opt/homebrew/...` в отслеживаемом проекте). `brew upgrade` незаметно меняет поставку; минимальная система бутылок Homebrew — вероятная причина `LSMinimumSystemVersion = 27.0` (`Info.plist:33`) при `MACOSX_DEPLOYMENT_TARGET = 26.2`. Профиль macos15 уже использует проверяемый по SHA python-build-standalone — его стоит взять и для современного профиля.

## 2. Средний приоритет

**M1. Выход зависает во время установки пакета Index 9B** — подтверждено.
`KatMacApp.swift:20-36`: `MacTerminationCoordinator` ждёт `shutdown()` без ограничения времени. `shutdown()` → `packages.pauseAll()` → `await queueTask?.value` (`PackageDownloadCoordinator.swift:552`), а очередь может ждать `indexMLX.assembleIfComplete()` (`:482`) — неотменяемую задачу сборки многогигабайтного пакета (`MacIndexPackage.swift:64-72`, `pause()` её не отменяет). Выход висит на «Завершаю работу…» до конца сборки и хэширования; при завершении сеанса — «Kat translator прервал выход». Исправление: отменять сборку при `shutdown`, ограничить ожидание ответа.

**M2. Нарезка на куски для MLX квадратична и не отменяется** — подтверждено.
`MLXTranslationBackend.swift:99-100` вызывает `TranslationChunks.plan` до проверки флага отмены; режим кусков включён по умолчанию (`:27`). В `TranslationChunks.swift:10-18` для каждого куска сначала токенизируется весь остаток, затем двоичный поиск с `high = chars.count` — ~log₂N токенизаций префиксов длиной до N символов, всё через Python под GIL. Длинная вставка (десятки тысяч символов) — секунды–десятки секунд; «Стоп», выгрузка и выход ждут на той же очереди. Исправление: ограничить `high` (например, `limit × 8` символов), токенизировать один раз со смещениями, проверять флаг между пробами. Сопутствующее: при ошибке Python `kat_mlx_count` возвращает `-1` и печатает трассировку (`MLXRuntime.c:53-60`), планировщик воспринимает это как «не помещается» и делит до отдельных символов — O(n) трассировок и ошибка «слишком длинно» вместо ошибки инференса.

**M3. Чтение выделения может заморозить интерфейс** — подтверждено по API.
`MacIntegration.swift:219`: `AXUIElementSetMessagingTimeout(root, 0.2)` задан только корню; фокусный элемент и родители (`:220-241`) используют таймаут по умолчанию ~6 с. `MacSelectedText` — `@MainActor`. Зависшее целевое приложение морозит Kat на секунды. Исправление: таймаут на системный элемент/каждый элемент или вынести вызовы с главного потока.

**M4. Буфер обмена: снимок с потерями, на главном потоке; запасной ⌘C** — подтверждено / на Mac.
`MacIntegration.swift:287-311`: снимок `[NSPasteboard.PasteboardType: Data]` теряет порядок типов (после восстановления меняется предпочтительный формат) и синхронно читает все типы на главном потоке — заставляет другие приложения материализовать ленивые данные (большие TIFF). Тип без данных или объём > 64 МБ молча отключают запасной путь. Ожидание копирования — 600 мс (`:267-276`): в Electron-приложениях копия может прийти позже, тогда в буфере остаётся выделение, а прежнее содержимое не восстанавливается. Восстановление скрытого элемента менеджера паролей сдвигает `changeCount` и, вероятно, ломает его автоочистку. Синтетический ⌘C использует код клавиши 8 (`:262`) — на Dvorak это ⌘J.

**M5. Захват области скрывает все окна и возвращает их в другом порядке** — на Mac.
`ScreenRegionCapture.swift:26-27, 70`: `NSApp.windows.filter { $0.isVisible }` → `orderOut`, затем `orderBack`. В список попадает окно `MenuBarExtra` и полноэкранное главное окно (скрытие ломает его Space); `orderBack` меняет порядок и может перетаскивать окна с других Spaces.

**M6. Внешний запрос перевода перезаписывает черновик и языки** — подтверждено.
`MacIntegration.swift:108-109` заменяет `model.languages` и очищает поле «Текст», `ConversationView.swift:278` ставит `typedText = integration.text`. Вызов из «Служб» или хоткея уничтожает несохранённый черновик и навсегда меняет целевой язык главного окна; в «Авто» это ещё и смена модели.

**M7. Сборка: Release с `ENABLE_TESTABILITY`, без strip; риски артефактов** — подтверждено.
- `generate-macos-project.py:68-69` ставит `ENABLE_TESTABILITY = YES` для Debug и Release (подтверждено в `project.pbxproj:506, 508`); прямой пакет собирается `xcodebuild build`, поэтому strip при установке не выполняется. Нужна отдельная конфигурация для тестов.
- `build-macos15-26.sh:7-8` перегенерирует **отслеживаемый** `KatTranslatorMac.xcodeproj` с профилем macos15 и восстанавливает его только в `trap EXIT`; если генератор в ловушке упадёт (`resolve_identity`) или процесс убит — следующая «современная» сборка соберётся с профилем macos15. Генерировать macos15-проект в `.build/`, как магазинный.
- `package-macos.sh:5-8` не сверяет профиль приложения (`KatBuildProfile`, `LSMinimumSystemVersion`) с `KAT_MAC_PROFILE` — можно упаковать современное приложение под именем `-macos15-26`.
- `bundle-macos-runtimes.py:21`: `rsync -aL` без `--delete`; после обновления torch/MLX/onnxruntime удалённые файлы остаются в бандле.
- `check-macos-bundle.py`: проверяет только абсолютные пути зависимостей (отсутствующий `@rpath`-dylib проходит и падает при запуске); `codesign --verify --deep` считает Mach-O в `Resources` данными — испорченная или ad hoc подпись вложенного кода проходит (`bundle-macos-runtimes.py:143` откатывается на `'-'` при пустом `EXPANDED_CODE_SIGN_IDENTITY`). Нет проверки TeamIdentifier, hardened runtime, timestamp, x86_64-срезов.
- `prepare-macos15-runtime.py:9-15, 27-33, 37-43`: ожидаемые SHA-256 берутся из ответа PyPI/GitHub при первом запуске и кэшируются в `.build` (доверие при первом использовании), проверка через `assert` отключается `python -O`. `:18-23`: копия окружения создаётся только если её нет — после обновления `IndexPython` старые пакеты смешиваются с MLX 0.32.2.
- `build-macos-runtimes.sh:7`: whisper.cpp/llama.cpp из `Dependencies/vendor` без проверки коммита (в отличие от `build-opus-runtime.sh`); `sherpa-onnx.xcframework` для macOS и `libonnxruntime.1.30.0.dylib` без хэшей; заголовки ONNX Runtime 1.28.1 при рантайме 1.30.0.

**M8. Вариант App Store: чтение выделения не проверено в песочнице** — пробел.
Магазинная сборка содержит тот же код: Accessibility-чтение чужих приложений и `CGEventPost` ⌘C (`MacIntegration.swift:73-76, 218-265`); проверки песочницы во время выполнения нет. В песочнице доступ к другим приложениям через AX, как правило, недоступен — функция молча не работает, запрос разрешения может вызвать вопросы ревью. Нужна проверка на магазинной сборке и запасной путь (Службы, буфер обмена).

**M9. OPUS GPU: SIGPIPE и отсутствие таймаутов** — на Mac.
`OpusGPUTranslationBackend.swift:83`: запись в stdin воркера без `F_SETNOSIGPIPE`/игнорирования SIGPIPE; если воркер завершился между проверкой `isRunning` и записью (гонка с отменой или падение), SIGPIPE убивает приложение. `response()` (`:49`) читает без таймаута; `kat_mlx_load` и планирование MLX не отменяются — зависший вызов Metal держит очередь, все запросы и выход ждут бесконечно. Ошибка запуска воркера (`Engine()` бросает исключение) приходит как ошибка инференса, а не загрузки модели.

**M10. Глоссарий превращает улучшение качества в полный отказ** — подтверждено (функция опциональная).
`index_glossary.py:128-130`: контекст > 1024 токенов, код `run == 1` или некорректный JSON → исключение → `MacGlossaryError`, перевод не выполняется, отката на обычный нет. Кандидат несёт 3 предложения контекста, а регулярное выражение считает OCR-блок без знаков препинания одним предложением — на длинных русских документах предел достигается легко.

## 3. Низкий приоритет

- Вставка изображения переводит значок файла Finder: `MacImages.swift:317` берёт `.png ?? .tiff`, а при копировании файла в Finder на доске — TIFF значка; URL файлов, PDF, HEIC, JPEG игнорируются.
- Автозагрузка модели на Mac не повторяется: `AppModel.swift:207` проверяет `NSApp.isActive`; если при запуске переключиться в другое приложение, автозагрузка пропускается навсегда (на iOS повтор есть при активации), первый перевод по хоткею платит полную загрузку.
- Сочетания внутри приложения зависят от раскладки при записи: `MacShortcuts.swift:18, 44` хранит `charactersIgnoringModifiers` — записанное в русской раскладке «⌘Щ» не срабатывает в ABC.
- Выход во время записи молча её отбрасывает (`AppModel.swift:530`), без подтверждения.
- В Mac-ошибках текст для iPhone: `AudioRecorder.swift:170` «…в настройках iPhone», `:81` «Телефон не успевает…»; нет кнопки перехода к настройкам микрофона.
- Заголовок пункта «Служб» не локализуется: `Info.plist:43-51` использует ключи `default/en/ru` внутри `NSMenuItem`, а локализация служб берётся из `ServicesMenu.strings`; ES/TR (и, вероятно, RU) видят английский заголовок при подсказке «Службы → Перевести в Kat translator» (`HotkeySettingsView.swift:54`).
- Многоканальный вход не сводится в моно: `AudioNormalizer.swift:42` без `downmix = true` — интерфейсы с микрофоном не на первом канале дают тишину.
- Двойной щелчок по заголовку окна всегда разворачивает его (`KatMacApp.swift:127-141`), игнорируя системную настройку.
- Абзацы теряются в режиме «целиком»: при превышении бюджета текст делится по `\n\n`, а склеивается пробелом (`MLXTranslationBackend.swift:111, 146-150`; Index 2B — `LlamaTranslationBackend.swift:90, 106`, это касается и iOS).
- `index_mlx.py:5-7` меняет `os.environ` (→ `putenv`) внутри многопоточного процесса — известный источник падений на macOS; задавать до инициализации Python.
- `index_mlx.py:52-64` заново применяет оптимизационные патчи omlx при каждом создании `Engine` (после каждого простоя и для второго стека MLX у изображений) — если патч не идемпотентен, функции оборачиваются повторно; omlx не в дереве, не проверено.
- x86_64-срез в arm64-приложении: `bundle-macos-runtimes.py:86` копирует универсальный `libsherpa-onnx-c-api.dylib` без `lipo -thin arm64`.
- `package-macos.sh:38` `hdiutil … -ov` молча перезаписывает опубликованный DMG той же версии; Release dSYM не сохраняется рядом с пакетом.
- `mac-signing.py:48-52` закрепляет лист-сертификат установленного приложения — после истечения годового Apple Development все сборки падают до явного переопределения; идентичность повторно определяется при упаковке и может отличаться от использованной при сборке.
- Манифест конфиденциальности приложения исключён из Mac-цели (`generate-macos-project.py:31`); добавляет ли его `install-sdk-privacy-manifests.py --platform macos` — не проверено.
- Исключение папки данных из Time Machine на Mac (корень `OfflineTranslator`, включая историю) — по решению владельца несущественно, оставлено как замечание.

## 4. Оптимизации (по ожидаемой пользе)

1. **Главное окно перерисовывается каждую секунду в простое.** `ConversationView.swift:26, 282`: таймер 1 Гц → `refreshPermissions()`; `MacIntegration.swift:155-161` присваивает `@Published` даже без изменения — весь `ConversationView` пересчитывается раз в секунду. Присваивать только при изменении, опрашивать при показанном предупреждении или при активации приложения.
2. **Нет `.pyc` в бандле.** `.pyc` исключены (`bundle-macos-runtimes.py:20`), запись отключена — при каждом запуске приложения и каждом старте OPUS-воркера stdlib, torch, transformers, mlx_lm компилируются из исходников. Предкомпилировать при сборке (`compileall --invalidation-mode unchecked-hash`) и запечатать подписью.
3. **OPUS GPU.** Модель направления перезагружается при каждой смене направления (`opus_gpu.py:54-63`) — в диалоге RU↔EN каждый ход; держать обе (Marian-big fp16 — сотни МБ). Любая отмена или ошибка (включая `tooLong`/`noSpeech`) убивает прогретый воркер (`OpusGPUTranslationBackend.swift:90, 133`) — нужна отмена внутри воркера (`StoppingCriteria` по флагу). Генерация по одному предложению с beam 5 — батчинг; лишний запрос `count`.
4. **MLX.** Нет `mx.set_cache_limit` и `clear_cache` после запроса; `BatchGenerator` обходит `wired_limit` mlx_lm — веса могут сжиматься/вытесняться в простое (возможное объяснение выбросов задержки из отчётов). Частичный вывод декодирует весь ответ на каждом шаге (`index_mlx.py:119-125`) — потоковый детокенизатор. Префикс инструкции заметен на 128-токенных кусках — переиспользовать его KV. Глоссарий пересобирается на каждый запрос, т. к. `TranslationDocument(text:)` получает новый UUID — ключевать по хэшу текста.
5. **Главный поток.** PNG-кодирование и декодирование захвата экрана (`ScreenRegionCapture.swift:61`, `MacImages.swift:55-57`; 6K-захват может превысить лимит 50 МБ — передавать `CGImage`), отрисовка картинки для истории с подбором шрифта шагом 0,5 (`MacImages.swift:159-177`), синхронное чтение файла до 50 МБ (`:312`), создание `AVAudioEngine().inputNode` (`AudioRecorder.swift:193-197`). Оверлей выделения перерисовывает весь дисплей на каждое движение (`ScreenRegionCapture.swift:97, 108-111`). Наблюдатель настроек реагирует на любую запись UserDefaults (`RoutedTranslationBackend.swift:35-41`).
6. **Сборка и размер.** Фаза «Bundle standalone Mac runtimes» с `alwaysOutOfDate=1` без входов/выходов — каждая сборка копирует гигабайты и переподписывает все Mach-O; штамп по хэшу источников. Явно задать `SWIFT_COMPILATION_MODE=wholemodule` и `DEAD_CODE_STRIPPING=YES`. Две копии ggml с встроенной Metal-библиотекой (whisper и llama), три дерева site-packages (`IndexPython`, `WayuPython`, `OpusPython`) с вероятными дублями numpy, вероятный дубль onnxruntime — дедупликация и `lipo -thin arm64`. `-j 6`/`-j4` → `sysctl -n hw.ncpu`; xz пересобирается на каждый запуск; `build-opus-runtime.sh:39` хранит все `*.previous-<ts>` бессрочно.
7. Вкладка «Изображение» держит снимок (~36 МБ пикселей + `NSImage`) после ухода с неё.

## 5. Архитектура и сопровождение

- Документация называет Index на Mac «воркером»; на деле встроенный интерпретатор с общим `sys.path`: `IndexPython` стоит раньше `WayuPython`, Wayu молча получает версии пакетов Index.
- Два стека `RoutedTranslationBackend` (сессия и изображения) — возможны два движка MLX или два OPUS-воркера; от этого защищает только порядок вызовов в `AppModel`, глобальной защиты резидентности нет.
- `DeviceProbe.swift:15, 21` на Mac откалиброван по GGUF 5,78 ГБ и llama.cpp, а работает MLX 4-bit 5,24 ГБ + MTP2.
- ID хоткеев = индекс `allCases` + 1 (`MacGlobalHotkeys.swift:46`) — перестановка enum молча переназначает действия.
- Одно состояние записи сочетания (`MacShortcutSettings.shared.recordingAction`) на два экрана настроек; запрос Accessibility и открытие панели приватности — в трёх местах; проверка «занято» (~15 условий) продублирована в `MacIntegration.unavailable` и `AppModel.requestScreenImage`.
- Нет определения песочницы во время выполнения — магазинная сборка не может адаптировать интерфейс.
- Ошибки сводятся к `-1`/`.inference` без вида ошибки, подробности только в stderr.
- Генератор Mac-проекта наследует граф объектов iOS и не чистит его: в `project.pbxproj` остаются виджет, «Embed Frameworks», «Install framework privacy manifests», «Bundle offline Thai frontend» (`:490, 511-512`); `HEADER_SEARCH_PATHS` дважды содержит `Dependencies/build/macos/headers`; проект зависит от игнорируемого `.build/macos-signing.xcconfig`.
- `CFBundleVersion` ведётся вручную в двух пространствах номеров (прямая 62, магазинная 76+) без проверки монотонности.
- Логика MTP находится в vendored omlx и в этом аудите не проверялась.

## 6. Что из iOS-аудита относится к Mac (общий код)

Применимо: **P3** «Отменить всё» удаляет давно докачанные модели; **P4** нечитаемый `history.json`; **P5** потоковая озвучка > 60 с не сохраняется; **M2** «Авто» на мощном устройстве без запасного OPUS (Mac почти всегда «мощный»); **M4** выбор модели до проверки пустой речи; **M5** неограниченное окно предпросмотра; **M6** незавершённая работа после отмены; **M7** запас 8 буферов в конвертации записи; загрузочные пункты M8, кроме `BGContinuedProcessingTask`/Live Activity; **M12** гонки под `@unchecked Sendable`; оптимизации 4.1 (перерисовки), 4.3, 4.6, 4.7; раздел 5 целиком.
Не применимо: P1, P2, P6 (жизненный цикл/аудиосессия iOS), M9–M11 (камера iPhone, тест устройства iOS, проба записи iOS), фоновые задачи iOS.

## Предлагаемый порядок работ

1. Проверить на Mac X1 (нажать ⌥1/⌥2/⌥3) и при подтверждении сменить значения по умолчанию; X2 — подписка на смену конфигурации аудио с сохранением записанного.
2. M1 (отмена сборки пакета при выходе + таймаут), M2 (нарезка кусков), M3–M4 (таймауты AX, снимок буфера вне главного потока), оптимизация 4.1 (таймер разрешений).
3. Сборка: отдельная Release-конфигурация без testability, macos15-проект в `.build/`, `rsync --delete`, усиление `check-macos-bundle.py`, закреплённые SHA в `prepare-macos15-runtime.py`; затем python-build-standalone для современного профиля (X5) и `.pyc` (4.2).
4. X3 (Developer ID + нотаризация) — когда понадобится раздавать прямой пакет другим; X4 и M8 — по результатам проверки памяти и магазинной сборки.

Каждое изменение проверять отдельно: сборка, тесты, установка поверх с сохранением моделей/истории/настроек, ручная проверка — согласно `docs/GIT_WORKFLOW.md`.
