# Index 9B на Mac: llama.cpp GGUF + MTP2 против MLX + MTP2

22 октября 2026. Mac M3 Pro, 18 GiB, macOS 27.0.1, питание от сети. Отдельный стенд: приложение не запускалось, история, настройки и модели не менялись.

**Вывод: MLX + MTP2 остаётся.** Путь iPhone (llama.cpp GGUF + MTP2) на Mac медленнее в **1,39 раза** — далеко за порогом перехода (10–15%), заданным владельцем.

## Что сравнивалось

- **MLX + MTP2** — текущий движок Mac: `shared/native/IndexMLX/index_mlx.py` (`Engine`), установленный пакет `index-translate-9b-mlx-mtp2` (5,22 ГБ), omlx из `.build/mac-index-mlx-mtp`.
- **llama.cpp + MTP2** — тот же `TranslationRuntime.cpp` + `IndexMTP.cpp`, что на iPhone (`KAT_IOS_MTP`), собранный для macOS из закреплённого llama.cpp `d81235049384…`; GGUF Q4_K_M `9cc6758b…` (5,78 ГБ). Сборка — `scripts/research/mac-index-runtime/build.sh`.
- **Контроль**: та же библиотека без MTP.

Одинаковые для всех: 30 фиксированных случаев RU/EN из [сравнения квантований](../index-quantization-2026-10-21/README.md), тот же промпт и суффикс, greedy, два прогревочных запроса исключены, два измеряемых прохода с перемешиванием по тем же seed, отдельный процесс на прогон, термо-гард (пауза при serious/critical, не потребовалась). Порядок прогонов чередовался: MLX → llama.cpp → MLX → llama.cpp → контроль. Стенд — `scripts/research/mac-index-runtime/bench.py`.

## Результаты

| Прогон | Загрузка, с | Проход 1, с | Проход 2, с | Медиана запроса, с | Первый токен (медиана), с | Пик Metal, GiB |

| MLX + MTP2 (B) | 3,58 | 50,38 | 50,36 | 0,842 | 0,326 | 5,92 |

| llama.cpp без MTP | 1,19 | 94,26 | 94,47 | 1,389 | 0,268 | 5,47 |

- Среднее время прохода: MLX **50,58 с**, llama.cpp + MTP2 **70,19 с** (×1,388). MTP2 в llama.cpp ускоряет на 34% относительно того же движка без MTP, но не догоняет MLX с его специализированными ядрами omlx.
- Повторяемость: выводы MLX A/B совпали 30/30, llama.cpp A/B 30/30, llama.cpp с MTP и без — 30/30 (MTP без потерь). MLX и GGUF — разные квантования весов, совпали 12/30; качество не сравнивалось.
- Загрузка llama.cpp при первом прогоне (8,5 с) включает холодное чтение GGUF; повторно — 3,1 с. MLX — 3,6–3,9 с.
- Физический footprint процесса у MLX выше (6,3 GiB против 0,55 GiB у llama.cpp), потому что веса MLX учитываются в footprint, а GGUF отображается через mmap; потребление Metal сопоставимо.
- Тепловое состояние всё время nominal, ожиданий термо-гарда 0.
