# Компактные модели под пары языков: RU↔EN и RU↔DE/FR/ES — 13 октября 2026

Запрос пользователя: искать небольшие локальные модели под конкретные языки. В приоритете RU↔EN, затем другие языки; проверка на Pixel.

Предыдущий отбор RU↔EN (7 октября) уже отбросил OPUS-MT small, Mozilla/Bergamot, T5 и Meta WMT19. Позже в приложение вошёл OPUS-MT Big EN↔RU/UK/BE. Здесь проверены новые кандидаты на том же наборе из 26 примеров с заданными фактами (24 коротких и 2 длинных, оба направления). Набор хранится в локальном архиве и в Git не входит. Дополнительно — две статьи: новость RU→EN и NASA «shake» EN→RU.

## RU↔EN: качество (ручная проверка фактов)

Примерное число критичных ошибок на 13 примеров в каждом направлении:

| Модель | RU→EN | EN→RU | Типичные ошибки |
|---|---|---|---|
| Index 9B | 0–1 | 0 | единственная правильно перевела «половине одиннадцатого» и «quarter past nine» |
| Index 2B | ~3 | ~1–2 | время словами, «сдача» → payment |
| Tower+ 2B | ~3 | ~3 | время, «зачитали карту», искажённая брань |
| OPUS Big | ~4 | ~3 | время, «не из аэропорта» → «not the airport», «charged» → «обвинили», «сдача» → «delivery» |
| Hy-MT2-1.8B | ~4 | ~2–3 | время, в одном случае смысл перевёрнут («если вы уже оплатили») |
| NLLB-600M | ~5 | ~3 | символы ⁇ вместо тире и кавычек, потеря смысла |
| EuroLLM-1.7B | ненадёжна | ненадёжна | префиксы «English:»/«Русский:», перевод в обратную сторону, длинный текст не переведён |

Время и числа, записанные словами, — общая слабость всех малых моделей. Новых малых моделей, явно лучше OPUS Big или Index 2B для RU↔EN, не найдено.

## Другие языки: прямые пары OPUS-MT Big

У Helsinki-NLP есть `opus-mt-tc-big` с прямыми парами без английского: zle-de/de-zle, zle-fr/fr-zle, zle-es/es-zle, а также it, pt, fi. Кроме того, есть пары EN↔ES/FR/IT/PT/TR/KO/AR/… Шесть направлений RU↔DE/FR/ES сконвертированы в CT2 INT8 (`model-store/research/opus-pairs`, по 235 МБ; тот же движок, что у OPUS в приложении).

Проверка на 8 фразах RU → DE/FR/ES и обратно (с Index 9B и 2B бок о бок):
- Качество близко к 9B и не хуже 2B. Например, «третий путь» переведён как «troisième voie» и «tercera vía»; у 2B там «tercer destino».
- Если подать два предложения одной строкой, OPUS теряет второе. В приложении OPUS и так делит текст по предложениям (`OpusSegments`).
- Мелкие ошибки есть: «vom dritten Weg», «два литра хлеба» в обратном переводе.
- Скорость на Pixel не мерилась. Ожидается как у OPUS EN↔RU: тот же размер и движок.

## Выводы

1. **RU↔EN**: оставить нынешнюю схему — OPUS Big для скорости, Index 9B для качества, Index 2B как середина. Новые малые модели не дают выигрыша.
2. **Другие языки**: прямые пары OPUS-MT Big RU↔DE/FR/ES (и далее IT/PT/FI, EN↔…) — самый практичный способ получить быстрый перевод для конкретных языков тем же кодом. Предложено подключить их на Android и проверить в приложении. Решение за пользователем.
3. Tower+ и NLLB доступны только по некоммерческим лицензиям; EuroLLM ненадёжна с этим промптом.

Сырые логи и полные выводы лежат локально: `.build/pixel-speed-audit-2026-10-12/{candidates,quality,runs/app-opus-speed}`. В Git не входят.
