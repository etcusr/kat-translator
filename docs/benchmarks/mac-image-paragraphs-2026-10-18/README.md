# Mac image paragraphs and diagnostics — 18 October 2026

Still-image OCR on Mac now reconstructs paragraphs before translation. The prior grouping limited a block to 23% of image height and fewer than 400 characters. On a short, wide text crop, one wrapped sentence was consequently sent as three unrelated translation requests. The new layout compares adjacent line geometry and size, joins soft wraps with spaces, and keeps separated blocks, list entries and different columns apart. Translation backends retain their existing token-aware input splitting for long text.

The editable translation pane removes line wrapping and leading/repeated whitespace within each translated paragraph. Reconstructed paragraphs remain separated; user edits are preserved. Copy/expanded text use the same cleaned text. Image overlays and exports use the reconstructed paragraph bounds. Live-camera grouping on iPhone remains unchanged.

With **diagnostics enabled**, the right pane shows recognition, translation and their sum. OCR timing starts after explicit OCR model/dictionary setup and includes detection/recognition and paragraph grouping; any initialization performed internally by Apple's recognition request is inseparable from that request. Translation timing sums backend processing time for this scene, excluding translator loading. Reused cached text has zero new translation time. Timings reset on a new scene/clear, survive result-preserving unload and exclude requests from superseded scenes. They are outside the editable/copied text.

## Evidence

- Actual Apple Vision recognition of the supplied screenshot crop reproduced three body-line requests with the old grouping. The revised grouping produces one complete body sentence without changing its words.
- The production Index 9B MLX/MTP2 runtime translated the same three separate lines in a summed **3.160 s**, versus **1.599 s** for the combined paragraph. The separate requests reproduced the dangling relative clause and isolated final phrase; the combined result has a single coherent sentence. This is one sequential comparison, not a repeated performance benchmark or a general quality guarantee. The model, weights and prompt are unchanged.
- OfflineCore: **326 tests, 2 opt-in skips, 0 failures**. New controls cover a narrow banner, long paragraphs, heading/font changes, whitespace, lists, separate columns, CJK, the actual one-request boundary, timing aggregation/cache/reset and superseded work.
- A second full screenshot with two news posts initially exposed an inset quote joining the body and varying glyph bounds splitting wrapped lines. Tighter left alignment and tolerance for glyph-height/vertical-overlap variation fixed those cases. The native-resolution OCR probe produces 40 lines and 13 translation blocks; no block crosses the gap between posts, the excerpt/footer remain separate, and body paragraphs are complete. RU→EN with the same production MLX/MTP2 runtime took **13.323 s** for all 13 blocks after **0.241 s** OCR, excluding model load. This is one run; metadata/channel labels remain translated as separate blocks.
- An additional real-app import exposed a short final word split from its paragraph: thumbnail-decoded OCR bounds differed from direct image decoding. Ink bounds of lowercase-only text can be almost half the height of an adjacent line with ascenders/descenders. The layout now tolerates that variation while retaining alignment, gap, heading and footer boundaries. A synthetic regression with three glyph-height variants failed before the change and passed afterwards. A fresh real-app import then passed: 13 blocks, no cross-post block, complete final sentence without an isolated repeated word; displayed OCR **0.546 s**, translation **14.253 s**. The earlier native-resolution runtime figures and this app measurement use different image decoding paths and are not a paired speed comparison; a separate build was also running during the latter. The temporary private-fixture test was removed after the run.
- Mac app verification: two runtime tests passed (real OCR → production translation/timings; early import/history/result lifetime) plus one UI test exercising diagnostics on and off with real translation. The displayed body remains a single paragraph; metrics are present only when enabled. An initial UI assertion read macOS StaticText.label instead of value and was corrected. A subsequent timeout exposed an early-import race during tab preparation; pending imports now resume when the image model activates, and the final run passed.
- Early imports no longer remain untranslated while package restoration is finishing. The image and pending request survive until the tab is ready; explicit clear removes the pending import.
- Final Store package verification is recorded in the [Apple release report](../../publication/apple-capture-store-2026-10-18.md).

Layout reconstruction is conservative geometry-based grouping, not general document understanding. Arbitrary multi-column reading order, complex tables and heavily indented layouts remain limitations. Only two supplied images and synthetic controls were used here; no broad OCR/translation accuracy claim is made. Private screenshot material, raw OCR text and local logs stay outside Git.
