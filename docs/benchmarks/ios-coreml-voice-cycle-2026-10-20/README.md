# iPhone: Core ML + Q8 в полном голосовом цикле — 20.10.2026

Исследовательская сборка **Kat Voice Lab**, отдельный bundle/container. Основная Kat не обновлялась. Проверка продолжает [сравнение ASR](../apple-whisper-acceleration-2026-10-20/README.md). Сначала проверен настоящий микрофон iPhone → Index 9B → воспроизведение Lessac; затем добавлен отдельный файловый вход для тихого сравнения одинакового PCM.

## Условия акустического блока

- iPhone 17 Pro, 12 GB, iOS 27.0.1; Release, entitlement increased-memory-limit.
- Зафиксированный исходный код `341b84594db45d07f995aff4d603870d77582d11`; последующие изменения основного проекта исключены.
- Контроль: native Whisper large-v3-turbo F16 с выключенным Core ML. Опыт: native Q8 + Core ML FP16 encoder, compute units `.all`. Это разрешение выбора устройств Core ML, а не доказательство исполнения всего encoder на Neural Engine.
- Index-Translate-9B Q4_K_M, RU→EN, автоматическая озвучка Lessac; экономия памяти **выключена**, исправление дат Whisper **выключено** в обоих вариантах.
- Обычная предварительная обработка во время записи и итоговая проверка распознавания включены одинаково. Декодирование, запись, перевод, TTS и обработка нехватки памяти взяты из исходного приложения; диагностические вставки и модельные пути находятся только в копии.
- Mac воспроизводит стимулы через динамики, iPhone записывает их микрофоном. После перевода Mac записывает реальное звучание iPhone. Это акустический стенд, а не импорт файла в приложение и не живая речь человека в момент теста.

## Обычный голосовой блок

Три повтора короткого вопроса и одна длинная реальная запись, затем новая запись после завершения всех циклов. Оба варианта прошли четыре цикла и повторное включение микрофона без ошибки. Короткие распознавания и переводы совпали дословно.

| Измерение | F16 | Core ML + Q8 |
|---|---:|---:|
| ASR короткого запроса, медиана трёх циклов | 2,28 с | 1,44 с |
| ASR длинного запроса | 5,39 с | 3,22 с |
| После остановки записи до завершения короткого цикла, медиана | 4,48 с | 3,95 с |
| После остановки записи до завершения длинного цикла | 25,14 с | 23,66 с |
| Максимум sampled process footprint | 2,68 GB | 3,14 GB |
| Минимум доступного процессу лимита выделения памяти | 3,77 GB | 3,30 GB |
| UIKit memory warnings | 1 | 1 |
| Загрузка ASR при запуске процесса | 17,30 с | 22,9 с |
| Повторная загрузка ASR после memory warning | около 1,0 с | около 1,3 с |

`asrSeconds` включает предварительное распознавание и итоговую проверку; это не только задержка после нажатия «Стоп». Полный цикл также включает перевод и длительность воспроизведения. Температурные категории различались: F16 nominal, Core ML после первого короткого цикла fair. Это наблюдаемые значения акустических циклов, не строгое измерение ускорения на одинаковом PCM. Для такого сравнения предназначен предыдущий ASR-отчёт.

На длинной записи оба варианта сохранили дату/время, но различались вступлением и добавили отсутствующий в исходном содержании хвост «Продолжение следует». Следовательно, работоспособность цепочки не означает безошибочное распознавание.

## Память

Полный цикл с Index 9B завершился, однако гарантировать постоянное одновременное нахождение всех моделей в памяти нельзя. В обычном блоке оба варианта получили memory warning; штатная логика выгрузила неиспользуемый ASR, закончила работу и автоматически загрузила ASR снова. Новая запись после восстановления работала.

В дополнительном блоке Core ML + Q8 получил два warning, в том числе во время длинной записи. Предварительная обработка приостановилась с сообщением, что запись продолжается; сама запись, окончательное распознавание, перевод и озвучка завершились. Подробные события и пределы памяти всех блоков находятся в [results.json](results.json).

Память снимается каждые 100 мс. Process footprint не учитывает полностью внешние службы Core ML; resident size и footprint имеют разный смысл. Доступный процессу лимит выделения — не свободная физическая RAM устройства. Наличие нескольких GB этого лимита не исключило системный warning. По результату Core ML + Q8 быстрее в ASR, но не экономнее F16 по footprint полного приложения.

## Даты и тихая запись

Дополнительный блок использует исходную проблемную запись, два синтетических контроля порядка «время→дата» / «дата→время» и повтор длинной записи. Синтетические контроли получены голосом Milena, rate 165; остальные записи реальные. Полные частные тексты и аудио не публикуются.

Первый тихий запуск исключён: исходная проблемная запись имела mean −40,1 dBFS / peak −19,6 dBFS, сохранённый trace не дошёл до вызова ASR; завершённых циклов нет. Это не результат качества Core ML. После сообщения о тихом звуке применена одинаковая нормализация **внешних стимулов** `loudnorm=I=-18:TP=-2:LRA=11` для обоих вариантов; пользователь также увеличил громкость. Обработка внутри приложения не менялась. Обычный и дополнительный блоки поэтому не являются контролем одной громкости.

Семантический эталон исходной даты — 15 декабря, 21:17, по ранее сохранённому согласованному независимому распознаванию; это не новая ручная дословная расшифровка. Для синтетических контролей эталон задан исходным текстом. Сравнение с F16 само по себе не является оценкой точности.

| Акустический вход | F16 без исправления | Core ML + Q8 без исправления |
|---|---|---|
| Исходная проблема: 15 декабря, 21:17 | Склейка `21.17.15 декабря`; перевод ошибочно 21 декабря, 17:15 | Та же склейка и тот же ошибочный перевод |
| Время перед датой: 22:18, 16 октября | Склейка `22.18.16 октября`; перевод восстановил правильные время/дату | `22.18.16`, потерян месяц; перевод сохранил время и день, но не месяц |
| Дата перед временем: 16 октября, 22:18 | Время/дата сохранены | Время/дата сохранены, но добавлен лишний хвост |
| Длинная запись: 18 октября, 23:30 | Время/дата сохранены; лишний хвост | Время/дата сохранены; лишний хвост |

Дополнительные четыре цикла и последующее включение микрофона завершились в каждом варианте. Пиковый footprint: F16 2,70 GB, Core ML + Q8 3,15 GB; warnings соответственно 1 и 2. F16 в этом повторном запуске загрузился за 0,69 с, Core ML + Q8 за 22,61 с: скорость старта зависит от состояния кэшей, первые загрузки нельзя обобщать на все запуски. Одинаковость файлов внешнего стимула не делает акустический сигнал на входе ASR побитово одинаковым, поэтому локальные различия нельзя однозначно приписать квантованию/Core ML.

## Одинаковые файлы: F16, Q8 без Core ML и Core ML + Q8

В отдельном тихом блоке выполнены **24 цикла**: четыре файла × два прохода × три варианта. Два файла — реальные записи (7,90 и 25,18 с), два — синтетические контроли порядка даты/времени (3,65 и 4,01 с). Все четыре хэша декодированного на iPhone mono 16 kHz Float32 PCM совпадают между вариантами и повторами. Внешняя нормализация громкости здесь не применяется. Нет захвата микрофона, синтеза речи или воспроизведения; исправление дат и экономия памяти выключены. Index 9B выполняет перевод после ASR.

| Измерение | F16 / Metal | Q8 / Metal, без Core ML | Core ML FP16 encoder + Q8 |
|---|---:|---:|---:|
| ASR: исходная дата, второй проход | 1,055 с | 0,954 с | 0,742 с |
| ASR: время перед датой | 1,180 с | 0,936 с | 0,698 с |
| ASR: дата перед временем | 1,084 с | 0,927 с | 0,662 с |
| ASR: длинная запись | 1,409 с | 1,214 с | 1,053 с |
| Сумма ASR четырёх файлов, второй проход | **4,729 с** | **4,032 с** | **3,155 с** |
| Сумма ASR + перевод, второй проход | 18,906 с | 15,723 с | 19,447 с |
| Максимальный sampled process footprint за весь запуск | **2,42 GB** | **1,60 GB** | **2,86 GB** |
| Температурная категория во всём trace | fair | fair | serious |
| UIKit memory warnings в завершённом запуске | 0 | 0 | 0 |
| Ручная повторная подготовка ASR | 0 | 0 | 0 |
| Загрузка ASR при старте этого процесса | 0,713 с | 0,489 с | 23,175 с |

Это по одному тёплому наблюдению на файл; первый проход сохранён вместе со вторым в [file-results.json](file-results.json). Порядок запусков: Q8 → F16 → Core ML + Q8. Q8 сократил сумму времени ASR относительно F16 на 14,7% в этой серии, footprint — примерно на 0,82 GB. Температура для этой пары одинакова, но серия мала и порядок не рандомизирован. Core ML завершил распознавание быстрее, однако **его состояние serious отличается от fair у контролей**: нельзя приписывать замедление перевода самому Core ML или выводить универсальное ускорение полного цикла. Загрузка модели показана отдельно, зависит от кэшей и не входит в сумму ASR.

На каждом файле во всех вариантах и обоих проходах **распознанный текст и перевод совпали дословно**. Совпадение не означает точность: исходная дата вновь склеена в `21.17.15 декабря` и ошибочно переведена как 21 декабря, 17:15; контроль «время перед датой» стал `22-18-16 октября` и тремя числами/датами в переводе. Контроль «дата перед временем» сохранил 16 октября, 22:18, длинная запись — 18 октября, 23:30. В файловом блоке лишний хвост «Продолжение следует» не появился. Это локальная проверка конкретных дат и сравнение вариантов, не WER на размеченном корпусе.

Первый тихий запуск Core ML при serious прерван после одного успешного файла: UIKit прислал memory warning уже после завершения цикла, ASR выгрузился, а тест ожидал только кнопку импорта. В исходном интерфейсе при неподготовленном ASR показывается кнопка подготовки. Тест теперь умеет нажать её и отдельно считает такое вмешательство; логика восстановления приложения не менялась. Повторный завершённый запуск тоже остался serious, но прошёл восемь файлов без warning и без нажатия подготовки. Прерванный запуск сохранён отдельно: отсутствие warnings в успешной таблице **не отменяет наблюдённую нестабильность по памяти**.

Файловый режим обходит запись/VAD/предварительное распознавание. Его footprint без TTS нельзя напрямую сравнивать с полным акустическим циклом как выигрыш от одного квантования. Q8 без Core ML показал здесь наименьший расход памяти при одинаковом результате; перенос в основной продукт не выполнен.

## Воспроизведение и ограничения

Помимо UI-ожиданий, проверяются события завершения проигрывания и запись звука динамика iPhone через микрофон Mac. Локальный CPU-only Whisper base использован как дополнительное свидетельство слышимого английского вывода; его ошибки форматирования чисел не считаются автоматически ошибками TTS. Это не независимая золотая расшифровка.

После акустического блока в iOS-копию добавлена кнопка **«Распознать аудиофайл»**, доступная при включённой технической информации. Она использует существующий Mac-путь импорта с системным выбором файла, проверкой длительности и отменой. Штатный декодер отдельно прошёл шесть тестов, включая WAV, M4A и MP3. При обычном запуске лаборатории и в файловом сравнении автоозвучка теперь выключена. Для отдельной проверки воспроизведения требуется явное включение.

До перехода на тихий режим завершились также восемь файловых циклов с озвучкой для Q8 и восемь для F16, без warnings. Тексты совпали; пиковый footprint составил 1,90 и 2,72 GB соответственно. Core ML успел завершить два таких цикла, после чего запуск остановлен по просьбе выключить звук. Этот незавершённый запуск исключён из сравнительной таблицы. Все эти файловые проверки обходят микрофон и не заменяют акустическую проверку выше.

Проверка относится к одному устройству, короткой серии и конкретным записям. Она не покрывает меньшую RAM, Bluetooth, фоновый режим, продолжительную нагрузку, TestFlight или App Review. Сырые журналы, xcresult, идентификаторы устройства, подписи, частные тексты и аудио остаются в игнорируемом локальном каталоге.

У основной Kat сохранились установленная идентичность и 846 записей метаданных моделей/голосов; удалённых путей нет. Полное равенство контейнера не подтверждено: между снимками добавилась запись истории, обновились download/package receipts и изменился `recordingPreviewVerification` (отсутствовал → false). Эти изменения не откатывались; стенд обращался к основному контейнеру только для чтения, происхождение различий не установлено. Это отдельный флаг проверки предварительного распознавания, не `whisperDateTimeRepair`, который в лаборатории явно выключен. Полные хэши файлов телефона не сравнивались.
