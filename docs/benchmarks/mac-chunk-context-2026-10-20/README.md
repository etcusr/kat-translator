# Mac Lab: разбиение длинного текста с контекстом

20 октября 2026. Отдельная тестовая Kat Translation Lab; Index 9B MLX/MTP2.
Основное приложение, модель, native runtime, Store-сборки не изменены.

## Что реализовано

В тестовом окне Index 9B доступны три режима:

1. **Целиком** — прежний промпт, один запрос; режим по умолчанию.
2. **По частям** — до 128 исходных токенов, обычный промпт каждой части.
3. **По частям с контекстом** — те же части, плюс до 64 предыдущих и 32
   последующих исходных токенов. Контекст переводится вместе с частью,
   но в результат попадает только текст между проверенными маркерами.

Границы выбираются по предложениям/строкам; длинное предложение делится
по словам, а длинное слово — по символам. Сохранённые исходные интервалы
позволяют проверить полное покрытие без перекрытий/пропусков. Для промпта
каждой части установлен запас: не больше 1024 входных токенов при общем
native-бюджете 2048. Отдельные части показываются по готовности;
до завершения статус явно обозначает неполный результат.

В первой пробе вариант «используй контекст, но не переводи его» добавил
контекст к результату, повторив и переставив реплики. Этот подход отклонён:
[пример ошибки](rejected-context-control.json). В сохраняемом варианте
модель должна вернуть ровно одну упорядоченную пару `[[KAT_START]]` и
`[[KAT_END]]`; отсутствующие, повторные, пустые или обратные границы дают
явную ошибку. Само сохранение маркеров не доказывает смысловую точность —
поэтому результаты дополнительно читаются и сравниваются с исходником.

Контекст ограничен соседними фразами. Это не память всего документа и
не память отдельных пользовательских запросов. Нет автоматического
переключения режима, скрытого изменения модели или подмены перевода.

## Сравнение

Берутся те же 16 обычных RU↔EN примеров и два граничных текста из
[предыдущей серии](../mac-long-context-2026-10-20/README.md). После отдельного
короткого прогрева каждый режим выполняется дважды, порядок перемешан
воспроизводимо: 18 × 3 × 2 запросов. Все режимы используют один постоянный
процесс, свежий контекст генерации каждого запроса и неизменные веса.

Сравниваются полное клиентское ожидание и момент первой **готовой части**,
полученной по протоколу прогресса. Это не время первого токена. В режиме
«Целиком» первым видимым результатом является весь перевод. UI получает
тот же прогресс и показывает завершённые части.

**108 запросов:** целиком — 32 успешных и 4 ожидаемых отказа лимита; без контекста — 36/36; с контекстом — 36/36. Все ответы одинаковы в двух повторах каждого режима, включая смысловые ошибки. Повторной загрузки модели не было.

Медианы двух повторов, полное клиентское ожидание / первая готовая часть:

| Текст | Целиком | Части | Части с контекстом |
|---|---:|---:|---:|
| Английский, 363 слова | 13.73 / 13.73 с | 14.70 / 3.99 с | 25.21 / 5.40 с |
| Русский, 305 слов | 11.72 / 11.72 с | 12.79 / 2.61 с | 22.87 / 3.56 с |
| Граничный, 689 слов | Ошибка лимита | 42.15 / 3.75 с | 74.92 / 5.11 с |
| Граничный, 767 слов | Ошибка лимита | 47.20 / 3.76 с | 84.46 / 5.11 с |

На десяти обычных длинных примерах медиана отношения полного времени к режиму «Целиком» — **1.04×** для частей и **1.67×** для частей с контекстом. Общего ускорения полного перевода не получено; первая часть доступна раньше.

В граничных текстах сохранены все **53/59 повторений** контрольных времён 09:25 и 11:25 в каждом успешном ответе. Проверены непрерывное покрытие исходных интервалов, ненулевой результат всех частей, допустимый размер каждого промпта и совпадение событий прогресса с префиксами окончательного ответа.

**Качество не сохранилось полностью:** в обоих режимах разбиения Марина стала названием отеля; контекстный режим улучшил передачу чуткого сна, но не исправил раздельные кровати/ночёвку и добавил более узкое earbuds вместо headphones. Поэтому «Целиком» остаётся режимом по умолчанию.

**Дополнительно 12 целевых запросов через границу части:** без контекста потерялись женский род Анны и значение «берег», с контекстом оба восстановлены. Это не устраняет ошибку Марины в более далёком контексте. [Целевые результаты](cross-boundary/results.json).

Полные переводы и поэтапные данные: [results.json](results.json).

## Границы выводов

Это небольшая синтетическая RU↔EN выборка, два повтора и один проверяющий
качества. Проверка одного и того же текста в разных режимах позволяет
сравнить изменения, но не гарантирует качество на иных языках/темах.
Нет чистой перезагрузки/изоляции GPU и непрерывного температурного контроля.
Store, телефоны, микрофон, озвучка и OCR не проверяются.

Прохождение граничных примеров не отменяет всех ограничений: остаются
лимиты ввода тестового окна, бюджета отдельной части и форматирования
ответа моделью. Ошибка или остановка не превращает частичный ответ в полный.
Автоматическое назначение контекстного режима не оправдано одним фактом,
что он умеет разбивать текст; решение зависит от замеров и качества ниже.

## Воспроизведение

```sh
python3 scripts/research/macos-translation-lab/test_chunking.py
python3 scripts/research/macos-translation-lab/compare_chunks.py .build/mac-chunks/results.json
python3 scripts/research/macos-translation-lab/summarize_chunks.py .build/mac-chunks/results.json .build/mac-chunks/report
python3 scripts/research/macos-translation-lab/build.py
```

GPU-проверки запускать последовательно. В меню примеров тестового окна
добавлены длинные тексты. `--probe-chunks OUTPUT.json` вызывает один из них
целиком и с контекстом через Swift-интерфейс процесса.
[Сборка, проверки и отпечатки](verification.json).

## Проверка реализации

- 8 тестов покрытия исходника, Unicode/длинных слов, границ абзаца и отказа на неверные маркеры.
- 32 прежних обычных перевода посимвольно совпали; повторное использование модели, таймер и восстановление после неверного запроса прошли.
- Пересобранное приложение: 2B/9B/повторный9B и целый/контекстный длинный пример через Swift-интерфейс, с совпадением ответов с основной серией. Это не автоматизация экранных кликов.
- Остановка процесса после первой из четырёх частей, последующий успешный перевод и завершение по EOF проверены.
- Подпись приложения, 8 файлов модели, неизменность native-кода/lockfile, Python compile и две проверки EN/RU-документации.
