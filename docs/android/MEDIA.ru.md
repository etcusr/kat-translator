# Офлайн медиа-runtime Android

[English](MEDIA.md) | **Русский**

На Android есть нативные адаптеры для существующей общей модели Whisper F16, голосов Piper/MMS и Supertonic, Meta Omnilingual, Silero VAD и ONNX-распознавателей PP-OCR, а также новый общий пакет детектора PP-OCR. Весь inference использует локальные файлы. Собственные медиа-движки приложения не используют системный TTS и онлайн-распознавание. Отдельный адаптер on-device SpeechRecognizer обрабатывает автоматический системный ASR, когда он доступен; реальные тесты Pixel RU/EN и ASR→OPUS проходят. Требования, замеры и ограничения — в research/platform-speech.md.

`bash scripts/android/setup-media.sh` проверяет официальный Android-архив sherpa-onnx 1.13.8, извлекает только две библиотеки arm64, скачивает закреплённые по дайджесту C-заголовки, затем собирает уже закреплённый исходник Whisper с NDK 28.2. Lock-файл — `Dependencies/android-media.lock.json`. Не подставляйте библиотеки Apple. Скачанный ONNX Runtime сообщает версию 1.28.2, поэтому lock намеренно отличается от 1.28.1 у Apple. Обе скачанные библиотеки имеют выравнивание ELF LOAD 16 KB.

У Whisper отдельная DSO со скрытыми символами и собственный закреплённый ggml. ggml и политика Vulkan у Index не менялись. Whisper на Android сейчас использует 4 потока CPU; это явный выбор backend ASR, а не запасной путь GPU для Index. Общий файл Whisper turbo F16 используется напрямую, без конвертации и дублирования. Параметры Whisper совпадают с Apple: жадное декодирование, без контекста, нулевая температура.

CMake подключает `media.cmake`; Gradle упаковывает его импортированные библиотеки. Из новых нативных обёрток экспортируется только `Java_org_openoffline_translator_inference_MediaNative_*`. Загрузчик использует стандартные байтовые массивы UTF-8, включая эмодзи и комбинируемые символы; встроенный NUL отклоняется. Флаги отмены находятся в общем владении C и живут до возврата синхронного нативного вызова. Каждая медиа-операция загружает и выгружает свою модель; UI должен выгружать Index и выполнять крупные операции последовательно, чтобы не перекрывать расход памяти.

## API

Все классы находятся в `org.openoffline.translator.inference`.

- `OfflineMedia.transcribe(modelPath, samples, language="auto")`: моно float PCM 16 кГц в `Transcript(text,language)`. Выбранные неподдерживаемые языки Whisper завершаются ошибкой.
- `transcribeOmnilingual(modelPath,tokensPath,samples,language)`: тот же контракт PCM. Язык выбирает вызывающий код; движок не даёт надёжного автоопределения.
- `synthesizePiper(model,tokens,dataDir,text)` и `synthesizeSupertonic(directory,text,language)`: `SpeechAudio(samples,sampleRate)`. MMS использует адаптер VITS/Piper со своими путями из каталога и пустым каталогом данных. Supertonic использует семь существующих файлов пакета и общую проверку 31 языка.
- `recognize(bitmap,detectorPath,recognizerPath,dictionary)`: нормализованные прямоугольники `OcrBlock` от верхнего левого угла и текст после CTC-декодирования. Словарь — общий преобразованный JSON.
- `cancel()` безопасен во время операции; `close()` ждёт рабочий поток.
- `PcmRecorder(vadModelPath?)`: разрешение на микрофон нужно до `start()`; `pause()/resume()/stop()`, конечный лимит 30 минут, `rms`, `elapsedMillis`, `speechDetected`, `lastSpeechMillis`, `failure`. С встроенным путём Silero `speechDetected/lastSpeechMillis` берутся из inference модели, а не только из амплитуды. Паузы не входят в длительность записи. Запись возможна только на переднем плане.
- `SpeechPlayer(context)`: потоковое воспроизведение float с фактической частотой движка, скорость 0,5–2×, пауза/продолжение/стоп и аудиофокус Android. `exportWav`/`writeWav` экспортирует существующий PCM16 WAV без повторного синтеза и без передачи исходных весов.

## Проверка и текущие ограничения

Нативные обёртки arm64 Whisper и медиа компилируются независимо. Kotlin компилируется. JVM-фикстуры покрывают CTC с Unicode/повторами символов, несовпадение словаря, шум/геометрию детектора, конечный PCM и заголовок/частоту/длительность WAV. Граничные случаи instrumentation покрывают загрузку библиотеки, флаги отмены, повреждённый Whisper и отсутствующий OCR. Выполнение на устройстве относится к корневой интеграции; сборка на хосте — это не результат качества речи, реальной камеры, маршрутизации, тепловой выносливости или задержки на устройстве.

Предобработка детектора PP-OCR — нормализация BGR/ImageNet с размерами, округлёнными до 32, и максимальной стороной 960. Связные компоненты вероятности становятся прямоугольниками по осям с отступами. Это работающее обнаружение горизонтального текста, но не полный паритет с Paddle contour/unclip/повёрнутыми прямоугольниками. Коррекция перспективы, автоматическое определение ориентации, группировка блоков и качество наложения ещё требуют фикстур на устройстве. UI должен давать ручной поворот/обрезку, где это нужно. Вызовы ORT для OCR и Omnilingual нельзя прервать посередине; отмена отбрасывает их результат после возврата вызова. Отмена TTS происходит на границах общего callback sherpa. Загрузку модели Whisper тоже нельзя прервать. Android теперь передаёт callbacks прерывания Whisper во все backend планировщика GGML (conv/encoder/cross/decoder) через сгенерированный патч исходника, который отказывает при несоответствии; исходники vendor/Apple не меняются. Раньше перегрузка планировщика проверяла отмену только после всего энкодера. Регрессия отмены в UI на Pixel вернулась в простой за 628 мс и приняла следующий запрос OPUS. Отмена до старта нативного кода тоже передаётся через границу публикации флага Java.

## Дополнительные общие голоса

OmniVoice теперь использует точную общую ревизию vendor 53e6c206 и патч отмены, отдельную Android DSO с собственным ggml, ту же модель Q8_0 + кодек и фрагменты по пять секунд. `bash scripts/android/setup-omnivoice.sh`, затем подключить `omnivoice.cmake` после `media.cmake`. API: `synthesizeOmniVoice(directory,text,language)`, 24 кГц. Его явный текущий backend на Android — CPU; Index остаётся на Vulkan. Точный общий пакет OmniVoice прошёл реальный синтез на Pixel 9 Pro 12.10.2026 (build14): малайская фикстура `Terima kasih.` дала 40 320 конечных отсчётов при 24 кГц (1,68 секунды), энергия 1874,166, работа синтеза/загрузки — 87,559 секунды. Он доступен как экспериментальный голос; даже короткая фраза может занимать больше минуты, и этот тест не подтверждает качество произношения носителя для каждого языка каталога.

Wayu переиспользует тот же акустический runtime C+ORT и неизменённый подготовленный тайский фронтенд (TLTK/PyThaiNLP/лексикон). `python3 scripts/android/setup-wayu.py` проверяет [официальный Android-архив Python 3.14.8](https://www.python.org/downloads/release/python-3148/), затем упаковывает stdlib и общий фронтенд в ZIP-ресурс APK размером 14,1 МБ, 1527 файлов. Lock-файл закрепляет и опубликованный архив, и дерево распакованного содержимого. Файлы акустической модели остаются в существующем общем скачиваемом пакете голоса. Подключите `wayu.cmake` после `media.cmake` и добавьте `.build/android-media/assets` в каталоги ресурсов приложения. Четыре DSO Python runtime импортируются через CMake; все их сегменты LOAD и модули расширений проверены на выравнивание 16 KB.

`WayuAssets.prepare(context)` проверяет и устанавливает в noBackupFilesDir только runtime, поставляемый в APK. Затем вызывается `synthesizeWayu(runtimeDirectory,directory,text,voice)`; голос по умолчанию `m_elderly_deep`, все 12 существующих голосов доступны через `OfflineMedia.wayuVoices`. Текст передаётся строкой Python и никогда не исполняется. Скачанный пакет голоса не может передать код. Встроенный Python инициализируется один раз на процесс, а акустические сессии выгружаются после каждой операции. Нативный инициализатор фронтенда Android заменяет только логику пути исполняемого файла и подключения фреймворка Apple. Фикстуры фронтенда Python 3.14 на хосте проходят 6/6; необязательные нативные движки arm64 компилируются. `WayuDeviceTest` проверяет одинаковые ID фонем тайского/английского и нормализацию чисел на реальном встроенном интерпретаторе.

Выполнение на устройстве, реальный синтез необязательных голосов, качество на слух и выносливость по памяти остаются отдельной интеграционной приёмкой. Core ML только для Apple не является backend Android. Из одной лишь компиляции не следует полный паритет функций с iOS или качество WER/CER/на слух.

## Выборочная приёмка на реальных моделях

`MediaPipelineTest` содержит отдельные методы `asr`, `piper`, `supertonic`, `ocr`, `wayu`, `omniVoice` для корневого запускателя с учётом нагрева. Класс никогда не начинает загрузки и не меняет настройки/историю. Он ждёт проверки хэшей каталога в PackageRepository, арендует точный пакет и сообщает идентичность backend и метрики результата. ASR использует только тестовую синтетическую WAV-фикстуру LJ Speech и проверяет слова отрицания/порядка/поезда; OCR создаёт HELLO WORLD через Android Canvas. Проверки голоса требуют конечного, не тихого PCM с фактической частотой движка и сохраняют WAV для прослушивания. Одних проверок PCM голоса недостаточно для оценки качества произношения.

Пути пакетов находятся во внешних файлах Android `packages/`: однофайловые пакеты используют `<id>.bin`, многочастные/архивные — `<id>/` с точными именами из манифеста. ID Whisper — `whisper-large-v3-turbo-f16`; ID OCR — `ppocr-v5-det` и `ppocr-v5-english`; голоса — `vits-piper-en_US-lessac-medium`, `sherpa-onnx-supertonic-3-tts-int8-2026-05-11`, `wayu-prosody`, `omnivoice-q8-base`. Wayu переименовывает четыре скачанных файла в имена существующего каталога `wayu-prosody.bin`, `wayu-curves.bin`, `wayu-decoder.bin`, `wayu-styles.bin`; это сопоставление имён файлов, без конвертации весов.

Для импорта фикстур на устройство разработчика `scripts/android/install-media-fixtures.py` сначала проверяет выбранные файлы хоста по общим каталогам. По умолчанию скрипт только печатает план. Явный `--install` размещает файлы в `/data/local/tmp`, затем запускает `AppOwnedPackageFixtureTest#importExactSharedPackage`, чтобы проверить и опубликовать файлы с владельцем — контекстом приложения. Никогда не создавайте внешние каталоги пакетов приложения через shell или `run-as`: проверенное пространство имён хранилища FUSE отклоняет такие пути. `--source ID=PATH` выбирает существующий общий файл или каталог; Index исключён. Корневой запуск должен выполнять импорт последовательно со всеми тестами на устройстве.

Текст MMS использует общий контракт без выбрасывания слов в `MmsSpeechText`: NFC, нижний регистр, явная проверка по словарю токенов, ограниченное нативное прописывание чисел и отклонение английского запасного варианта ICU. Закреплённая публичная зависимость `com.ibm.icu:icu4j:78.3` даёт `RuleBasedNumberFormat`; SDK Android этот класс не предоставляет. Версия проверена по [метаданным Maven Central](https://repo.maven.apache.org/maven2/com/ibm/icu/icu4j/maven-metadata.xml), API — по [официальной документации ICU](https://unicode-org.github.io/icu-docs/apidoc/released/icu4j/com/ibm/icu/text/RuleBasedNumberFormat.html). `MediaLanguageDeviceTest` и JVM-тесты на хосте проверяют прописывание на тамильском и отклонение запасного варианта. Эталон тамильского `12` — точное правило количественных числительных в [ICU release-78.3 ta.txt](https://github.com/unicode-org/icu/blob/release-78.3/icu4c/source/data/rbnf/ta.txt#L32), также проверенное запуском закреплённого JAR на хосте. В ICU4J 78.3 нет правил чисел Apple для бенгальского, каннада, панджаби и маратхи; цифры на этих языках сейчас нужно писать словами. Произвольные буквы или неподдержанные числа вызывают ошибку до синтеза, а не исчезают молча.

## Живая камера Android

`org.openoffline.translator.android.camera.LiveCamera` использует Camera2 напрямую: реальный предпросмотр TextureView, непрерывная фокусировка задней камеры, замер по касанию и ограниченный цифровой зум. Он выдаёт выровненные по вертикали кадры YUV для OCR не чаще чем раз в 350 мс, максимальная сторона 1600, с одним необработанным `CameraFrame`, пока потребитель его не закроет. Поздние кадры и снимки аннулируются по номеру сессии. Затвор снимает JPEG через отдельный ImageReader; ImageDecoder один раз применяет EXIF и ограничивает выровненный bitmap размером 3072. Помощник не записывает кадры на диск.

Все публичные методы и callbacks выполняются в главном потоке; сессии камеры, преобразование YUV и декодирование JPEG — в закрытом handler. UI владеет разрешением CAMERA, `start`, `stop` по жизненному циклу и `close` при освобождении. UI должен закрывать каждый CameraFrame в блоке finally рабочего потока, отключать доставку кадров во время другой нативной работы и владеть/освобождать Bitmap, возвращённый `capture`. `stop` освобождает сессию, readers, поверхности и камеру; `close` также снимает регистрацию callbacks дисплея и завершает свой handler. Исходные API — по [предпросмотру Camera2](https://developer.android.com/media/camera/camera2/camera-preview) и [ImageDecoder](https://developer.android.com/reference/android/graphics/ImageDecoder).

`ImagePerspective.rectify` принимает четыре явных нормализованных угла (по часовой стрелке, начиная с верхнего левого) для замороженного/импортированного снимка и отображает их в ограниченный прямоугольник. Он проверяет выпуклость и отклоняет пересекающиеся/вырожденные точки. Это явная геометрия пользователя, а не автоматический детектор документа. Группировка абзацев OCR теперь использует те же пороги, что и общий `HybridOCR.swift`. Более широкий языковой охват Vision у Apple по-прежнему не является движком Android; Android направляет только к реально установленным распознавателям каталога.

Тесты: CameraGeometryTest покрывает ориентации, обратное отображение, фокус с учётом обрезки, цвет YUV и неверные точки перспективы. CameraPixelsDeviceTest использует сгенерированные пиксели для границ JPEG, исправления прямоугольника и владения кадрами. LiveCameraDeviceTest требует выданного root разрешения CAMERA и монопольного доступа к оборудованию: реальный предпросмотр, снимок, приостановленная доставка и stop/reopen. Он не сохраняет и не логирует пиксели.

Инициализация Wayu на Android изначально падала, потому что CPython не находил `Asia/Bangkok` в каталоге часовых поясов POSIX. Ресурс теперь включает полный собственный wheel `tzdata` 2026.5 (закреплённый SHA в медиа-lock) вместе с лицензиями. Это соответствует [стандартному запасному источнику zoneinfo](https://docs.python.org/3/library/zoneinfo.html#data-sources); ни логика тайского фронтенда, ни смещение часового пояса не подменялись. Запуск на хосте с пустым `zoneinfo.TZPATH` подтвердил встроенные данные Бангкока и все шесть общих фикстур фронтенда. Приёмку фронтенда на устройстве нужно повторить с новым APK.

## Корректность OmniVoice на базовом ARM64

Закреплённый помощник GGML `ggml_vdotq_s32` при сборке без DOTPROD группировал произведения иначе, чем SDOT. Хотя целочисленная сумма совпадала, значения по lanes различались. Накопление с плавающей точкой Q8 затем давало другие токены MaskGIT: точная общая малайская фикстура `Terima kasih.` декодировалась с сырой энергией около `2.25e-5` на Pixel, и удаление тишины правильно её отклоняло.

`omnivoice_cpu_compat.h` переопределяет только этот помощник в закрытой цели `ggml-cpu` OmniVoice. Попарные расширяющие суммы теперь сохраняют четыре смежных произведения в каждом lane SDOT. Это использует базовый ARM64 NEON, не требует расширений DOTPROD/FP16 и не меняет Index, Whisper, общие исходники vendor и оба исходных файла Q8 GGUF. Настройка проверяет закреплённую точку привязки запасного пути перед применением адаптера.

Контролируемые результаты на хосте с теми же моделями, seed и текстом:

| Конфигурация CPU | Хэш токенов | Сырая энергия аудио | Результат |
| --- | --- | ---: | --- |
| ISA Apple по умолчанию, без BLAS/Accelerate | `1c7090618c51ce37` | 3341.73 | 1,68 с аудио |
| Базовый ARMv8-A | `1eac351f3cbaa13c` | 0.000026 | отклонённая тишина |
| Базовый + только FP16 | другой | 0.000027 | отклонённая тишина |
| Базовый + только DOTPROD | `1c7090618c51ce37` | 3341.62 | 1,68 с аудио |
| Базовый + исправленный помощник NEON | `1c7090618c51ce37` | 3341.62 | 1,68 с аудио |

Подача хорошей фикстуры токенов в исходный базовый декодер тоже дала нормальный звук, что независимо локализовало сбой в генерации токенов, а не в усилении декодера или порогах тишины. Обходное усиление не применялось. `bash scripts/android/test-omnivoice-dot.sh` проверяет 10 032 асимметричных, экстремальных и случайных вектора против независимой скалярной эталонной реализации для каждого lane; старый помощник проваливает 40 024 сравнения lanes. Исправленная библиотека Android компилируется. Исправленная библиотека прошла `MediaPipelineTest#omniVoice` на реальном Pixel 9 Pro в build14: 24 кГц, 40 320 отсчётов, энергия 1874,1661436266738, 87,559 секунды работы синтеза/загрузки, `OK (1 test)`. Использованы точные исходные файлы Q8. Доказательство на устройстве: `.build/android-parity-device/omni-build14.log`. Backend каталога теперь можно включать с оговоркой «экспериментальный/медленный». Локальные численные контроли — в `.build/android-media/omni-*.log`. Подробная промежуточная диагностика сохранена в этой отладочной контрольной точке; глобального усиления или ослабления порога тишины не применялось.

## Android 0.3.2: OCR и речь с явным языком

Пользователь попросил убрать автоопределение языка и из камеры, и из речи. `currentSource` превращает прежнее/текстовое `auto` в последний явно выбранный язык, показанный в выборе языка; строка «Авто» доступна только в текстовом режиме. Снимки с микрофона, итоговое распознавание с микрофона и импорт аудио используют этот явный язык. Автоматический выбор backend сохранён и определение языка не запускает.

ML Kit Text Recognition v2 16.0.1 встроен для пяти письменностей, выбор — через `OcrRouting`. `MlKitOcr` держит только клиент текущей письменности, с владением bitmap на время задачи и подсчётом ссылок на выведенные клиенты при отмене/переключении. Угадывания письменности и многопроходного OCR в продукте нет. Общий OcrLayout нормализует группировку/наложение. Для русского предпочитается проверенный установленный `ppocr-v5-mobile-det`, с переходом на существующий установленный серверный детектор, только если мобильного пакета нет. Веса распознавания и словарь не меняются. Источники и доказательства — в OCR-OPTIONS.md и benchmarks/2026-10-12-hybrid-ocr/.
