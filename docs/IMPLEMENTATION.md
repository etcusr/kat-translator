## Решения и отклонения от плана

1. Работа в новой локальной ветке `work/whisper-ios` этой директории вместо отдельного worktree: исходно репозитория и чужих изменений не было; удалённый репозиторий не затрагивался.
2. Ядро и XCTest вынесены в локальный Swift package с запуском на Mac вместо отдельного iOS XCTest target: установленного Simulator runtime нет. iOS-сборка проверяется отдельно; это не аппаратные испытания.
4. XCFramework собирается upstream CMake для iOS device/arm64 Simulator вместо общего upstream-скрипта: тот включает Core ML и лишние платформы. Здесь Core ML выключен; Metal source встроен.
5. Возобновление сохраняет сетевую политику исходной задачи URLSession; изменение Wi-Fi/mobile требует новой загрузки и объяснено в UI. Приватный формат resume data не модифицируется.
6. Сначала хранение/загрузчик проверялись через Swift package, затем интегрированы Xcode shell и native backend. Номера коммитов могут объединять части задач; состояние определяется файлами и проверками, а не названием коммита.
7. Независимое ревью — один финальный проход после последовательной реализации, согласно выбранному пользователем способу исполнения.

## Проверки регрессий

- Неверный SHA, обрезанный файл, восстановление staging и повторная проверка изменённого установленного файла.
- Старые callbacks после отмены не меняют текущую generation; готовность появляется только после проверки.
- Преобразование stereo48k → mono16k с завершением конвертера: первоначальный вариант терял хвост, исправлен `finish()`.
- Отменённый текст не публикуется; инференс не запускается параллельно; каждый вызов unload ждёт освобождения контекста.
- p50/p95 и экспорт версий без текста/аудио. `processingSeconds` теперь охватывает конец записи → результат, `inferenceSeconds` хранит время только Whisper.

История RED/GREEN доступна локально в `.build-logs/`; журналы и сборочные файлы не входят в Git. Результаты устройства нельзя подменять успешной компиляцией.

Личный Team хранится только в `Config/Signing.local.xcconfig` (исключён из Git); общий проект подключает его через optional include. Учётная запись и сертификат остаются в Xcode/Keychain.

## Обновление: полный конвейер — 6 октября2026

Этот раздел переопределяет исторические ASR-only статусы выше. Пользователь уже запускал ASR-прототип и выгрузил7реальных замеров; файл в корне оставлен без изменений.

Реализованы полноценный путь запись→Whisper→TranslateGemma→Piper→динамик, RU↔EN, оригинал/перевод, копирование перевода, повтор озвучки, диагностика текстом и отчёт схемы2. Настройки держать/нажать,300с максимум и10с без речи; начальная тишина останавливается безASR. VAD локальный, bundled643854bytes.

Модули: `ConversationPipeline` владеет последовательностью и жизненным циклом; нативные backend queues сериализуют вызовы. Отмена инвалидирует generation, прекращает звук и ждёт активный вызов перед unload/delete. `RecordingStartGate` удерживает незавершённый startup после отмены до его возврата; новое нажатие не объявляет no-op успешным. Ошибка смены голоса очищает идентичность загруженного голоса.

MT использует2048токенов контекста,1536максимум входа и512выхода с учётом шаблона; точный tokenizer определяет разделение. Источник токенизируется без специальных управляющих токенов. U+0000 явно отклоняется. При исчерпании выхода безEOS частичный ответ отбрасывается, источник делится снова. TTS получает части до180Characters, при>60с делит текст повторно. В памяти только текущий PCM-фрагмент; между частями возможна пауза. Whisper получает весь PCM до4,8M samples и обрабатывает свои окна самостоятельно.

Пакеты: старое хранилище Whisper и background ID сохранены. MT отдельный файл, два проверенных tar.bz2голоса; ограниченный tar parser разрешает только обычные файлы/каталоги и проверяет каждый хеш перед atomic publish. Готовность голосов повторно проверяется при холодном запуске. Runtime pins в `Dependencies/runtime.lock.json`; модели в каталоге/манифестах.

Осознанные ограничения: программная отметка запуска озвучки, без измерения физического динамика; отдельного времени последнего токена нет (`mtSeconds` включает весь MT). Нет прогресса Whisper по процентам. Сетевые HTTP404/restart/фоновые проверки ещё открыты. Экономия памяти явная, без скрытого переключения. Настройки закрываются с выгрузкой моделей; затем нужна повторная подготовка. Экспорт не содержит текста/аудио.


## История, озвучка и голоса — актуальное дополнение

`TranslationHistory` — actor с атомарным JSON-индексом и потоковой записью AAC/M4A, независимыми лимитами текста/аудио и приватными копиями для отправки. Дефолты: 100 текстов, 10 аудио, 30 дней; 0 отключает соответствующий лимит. На iOS включена защита файлов. Завершённый текст сохраняется до синтеза, полный аудиофайл публикуется после окончания озвучки. Незавершённые файлы удаляются при отмене/восстановлении.

`SpeechPreparation` выдаёт короткую первую часть (до 90 символов), затем части до 180 с повторным делением слишком длинного аудио. Pipeline держит текущий и один следующий PCM, синтезирует следующий при воспроизведении текущего, отменяет и дожидается задачи перед unload. `SpeechPlayer` сохраняет движок на всю реплику. `SpeechSilenceLimiter` ограничивает длинную внутреннюю тишину примерно 1 секундой; короткие паузы и защитные края сохраняет.

Настройки голосов: четыре встроенных M4A-образца, отдельные загрузки и сохранённый выбор RU/EN. Denis/Irina и LJ Speech/Lessac проходят проверку архива и каждого файла. Выбор применяется только для готового пакета; выгружается только текущий TTS. Закрытие настроек само по себе больше не выгружает ASR/MT. Тяжёлые веса исключены из Git, четыре небольших образца включены.

Отчёт схемы 3 записывает фактический голос, ожидание очереди и сокращение тишины; группы не смешивают голоса/режимы памяти. История хранит текст/аудио по запросу пользователя, диагностический экспорт их по-прежнему не содержит.

Проверка: 53 XCTest, 0 ошибок и пропусков с реальными архивами. В тестах подтверждены prefetch во время заблокированного playback, ожидание отменённого синтеза, целостность M4A, независимая очистка и сохранность аудио после ошибки последующей записи индекса. Одно независимое финальное ревью обнаружило 1 P2; воспроизведён RED и исправлен GREEN. Журналы `.build-logs/history-review-red.log`, `history-reviewed-tests.log`, `history-reviewed-signed-build.log`. Аппаратная скорость и качество после изменения требуют нового прогона; ограничения перечислены в `DEVICE_TESTING.md`.

## Автоматическое направление RU ↔ EN

По прямому запросу пользователя добавлено ограниченное расширение существующего сценария. «Авто RU ↔ EN» запрашивает Whisper с `language="auto"`, `translate=false`, `detect_language=false`. Последний флаг намеренно false: в закреплённом whisper.cpp true завершает full после определения без транскрипции. После полной обработки читается `whisper_full_lang_id`; языки кроме ru/en отклоняются, без молчаливого fallback. Нативная очередь/отмена остаются прежними.

ASRBackend принимает optional language: nil — авто. Pipeline дожидается ASR, выбирает source/target, только затем вызывает MT и голос; историю сохраняет с фактическим source. Направление текущей записи захватывается при старте; не меняется вслед за UI. Ручной режим сохраняет указанный язык. Введённый текст в авто явно отклоняется, дополнительный системный детектор языка не добавлен. Выбор режима сохраняется отдельно от направления предыдущего результата.

Отчёт схемы 4 различает auto/manual, фактический source и неустановленное направление (unknown в группах, отсутствующий source в операции). Авто и ручные замеры не смешиваются. `asrSeconds` включает определение языка. Проверки: RED воспроизвёл старое принудительное RU-направление, GREEN проверил последовательную смену EN→RU / RU→EN, голос, историю, отсутствие MT/аудио при ошибке определения и отсутствие угадывания языка введённого текста. Всего 57 тестов с реальными архивами; журнал `.build-logs/auto-language-final-tests.log`. Нативный вызов проверен iOS-сборкой, точность модели в новом режиме требует живого прогона.
