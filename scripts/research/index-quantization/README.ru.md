# Отдельное сравнение квантования Index

[English](README.md) | **Русский**

Стенд читает только явно указанные GGUF и библиотеку TranslationRuntime. Он не запускает Kat, не читает историю/настройки, не заменяет модели и не меняет поведение приложения. Корпус: 30 заранее заданных русско-английских примеров с происхождением; [протокол](../../../docs/benchmarks/index-quantization-2026-10-21/PROTOCOL.md).

Соберите `Memory.mm` как dylib с Foundation и Metal. Пути перечислены в `run.py --help`. Каждый запуск требует нового выходного файла: старые результаты не перезаписываются. Везде задавайте `GGML_METAL_NO_RESIDENCY=1`. Модели запускаются последовательно с одной библиотекой, измерителем и корпусом: два измеряемых прохода после двух прогревочных запросов. Не совмещайте замеры со скачиванием/компиляцией. До запуска сверьте SHA-256 с метаданными закреплённой официальной ревизии.

`python3 scripts/research/index-quantization/summarize.py PRIVATE_RESULTS_FOLDER` проверяет четыре прогона, создаёт сводку, анонимизированные переводы и отдельный ключ вариантов. Сначала оцените сохранность смысла, потом откройте ключ. Автоматической оценки качества перевода скрипт не выставляет.

Память показана раздельно: `footprint` — учитываемая физическая память; `resident` — резидентная память с отображёнными файлами; `resident_process_peak` — максимум за жизнь процесса; `metal_allocated` — счётчик выделений Metal, не дополнительная физическая RAM для сложения. Интервал 100 мс может пропустить короткие пики. Скачивание/хэширование исключены из времени, загрузка модели измеряется отдельно. Сохраняются swap и тепловое состояние. Это измерения GGUF-движка на Mac, не приёмка Mac MLX/MTP2 или приложения iPhone.
