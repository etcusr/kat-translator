# Отдельный стенд полного голосового цикла на iPhone

[English](README.md) | **Русский**

Эксперимент собирает зафиксированную закоммиченную версию Kat в `.build` с отдельным идентификатором `app.kattranslator.voicelab` и названием **Kat Voice Lab**. Он не должен заменять Kat или писать в её контейнер. Незакоммиченные изменения основного каталога исключены.

Сохраняются запись, предварительная обработка и проверка речи, перевод Index 9B, потоковый синтез, проигрыватель и реакция на нехватку памяти. Отличаются только модель/библиотека ASR, идентификатор/настройки стенда и диагностические вставки. Экономия памяти и исправление дат/времени выключены; направление RU→EN задано явно, английский голос — Lessac. Энкодер Core ML имеет точность FP16; полный файл нативной модели — Q8.

## Подготовка

1. Создать пустой `.build/<эксперимент>/source` через `git archive <коммит>`, записав коммит. Включить `apps`, `shared`, `assets`, `scripts`, `docs`, `tests/fixtures`, `PROJECT_DESCRIPTION.md`. Связать `Dependencies` с существующими результатами сборки, используя их только для чтения; конфигурацию подписи задать локально. Не копировать личные данные или историю Git.
2. Один раз выполнить `prepare.py <snapshot> --native-build <isolated-whisper-ios-build>`. Скрипт проверяет точное совпадение замен. Использовать сборку и модели [предыдущего эксперимента Whisper](../apple-whisper-acceleration/README.ru.md).
   Для диагностического файлового входа затем один раз выполнить `enable_file_import.py <snapshot>` до сборки.
3. Собрать созданный iOS-проект для тестирования в отдельный DerivedData; команду разработчика указать локально. Проверить идентификатор, подпись и разрешение на повышенный лимит памяти.
4. Выполнить `provision.py`, передав устройство, рабочий каталог, локальный model-store/downloads и исследовательские модели Whisper. Скрипт устанавливает только стенд и копирует Q8, скомпилированный энкодер, Index 9B, архивы Irina/Lessac, квитанции и контрольный F16 в его контейнер. Штатная проверка файлов моделей остаётся включённой.

В каталоге стенда используются отдельный Q8 ID и точная контрольная сумма, а URL загрузки заведомо недействителен: модели предоставляются локально. Ошибка загрузки требуемого Core ML аварийно завершает эксперимент, скрытый переход на Metal запрещён. Контроль F16 явно отключает Core ML и использует отдельный локальный файл.

## Акустическая проверка

Для обычных сравнений используйте файловый вход ниже. Воспроизведение через динамики — отдельная проверка микрофона, мешающая прослушиванию на Mac; это не способ запуска бенчмарка по умолчанию.

Использовать `run.py --device ... --work ... --name <новое-имя> --short <audio> --long <audio> --capture-output`, для контроля добавить `--baseline`. Разблокированный iPhone должен лежать рядом с динамиками Mac. Тест нажимает настоящий микрофон, разрешает доступ только стенду, записывает три короткие и одну длинную реплику, ожидает озвучку перевода и проверяет следующую запись. Mac воспроизводит внешние звуковые стимулы; аудио не импортируется в приложение. Дополнительная запись микрофоном Mac даёт независимое свидетельство выходного звука. Происхождение обоих стимулов следует записать. Четыре аргумента `--date-input` задают дополнительный блок: исходная проблемная запись, время перед датой, дата перед временем и повтор длинной реплики. Для слышимости внешние стимулы этого блока нормализованы через `loudnorm=I=-18:TP=-2:LRA=11`; запись и распознавание в приложении не изменены.

`ResearchTrace.swift` каждые 100 мс измеряет физический footprint, его максимальное значение за жизнь процесса, resident memory, доступный процессу бюджет iOS и температурную категорию. Отмечаются запись, загрузка/распознавание/выгрузка ASR, предупреждения о памяти и завершение воспроизведения. Метрики цикла и личные транскрипты сохраняются локально; штатный журнал TTS дополняет измерения. Контроль F16 определяется по записи запуска: метрика каталога по-прежнему содержит Q8 ID стенда, поэтому фактические веса нельзя определять только по ней.

Проверить завершение всех циклов, содержание исходного текста/перевода, непустое синтезированное аудио, завершение проигрывания и повторную запись. Разделять первый и повторные запуски; учитывать предупреждения, перезагрузку ASR и температуру. Акустический вход различается между прогонами, поэтому это не сравнение скорости на идентичном PCM. Доступный процессу бюджет не равен всей свободной RAM; footprint не включает внешние службы Core ML.

Аудио, транскрипты, сырые журналы, подписанные сборки, идентификаторы устройства/подписи и веса остаются вне Git. Публикуются только обезличенные итоги. После проверки сверить файлы/настройки основной Kat. Не загружать стенд в Store и не отправлять на ревью.
## Импорт файла без воспроизведения на Mac

После `prepare.py` однократно выполните `enable_file_import.py <snapshot>` до сборки. Он включает существующий путь Mac `AudioFileImport` / `AppModel.importAudioFile` только в копии iOS-лаборатории. При включённой технической информации под микрофоном появляется **«Распознать аудиофайл»** с подписью диагностики. Системное окно выбирает файлы из «Файлов»/iCloud с security-scoped доступом; ограничения длительности, декодирование и отмена сохраняются. Импорт обходит микрофон, VAD и предварительную обработку во время записи; метрика `inputMode: audio-file` отличает его от проверки микрофона.

Лаборатория показывает собственную папку Documents в «Файлах». Перенесите четыре записи в `Documents/AudioTests`: `01-date.wav`, `02-time-first.wav`, `03-date-first.wav`, `04-long.wav`. Секреты в эту папку не помещать. Этот блок не требует нормализации громкости. Журнал считает хэш фактически декодированного mono PCM 16 kHz для проверки одинакового входа.

Запускайте последовательно `run_files.py --device ... --work ... --name files-<variant> --variant <variant> --repeats 2` для `f16`, `q8`, `coreml-q8`. UI выбирает файлы, распознавание и перевод Index 9B выполняются на iPhone. По умолчанию автоозвучка выключена и в лаборатории, и в файловых тестах; `--speak` включает её только для отдельно запрошенной проверки воспроизведения. Скрипт не воспроизводит и не записывает звук на Mac. `q8` явно выключает Core ML и использует native Q8; `f16` также выключает Core ML и выбирает отдельный F16-файл. Обычный запуск лаборатории остаётся `coreml-q8`.

После всех трёх тихих прогонов используйте `summarize_files.py <work> <output.json>`: он требует восемь успешных циклов на вариант, одинаковые PCM-хэши, метрики файлового входа, отсутствие запуска микрофона и воспроизведения. Частные результаты распознавания/перевода проверяются отдельно: точное совпадение не является оценкой точности.

Если давление памяти в простое выгрузило распознавание, UI-тест может нажать существующую кнопку подготовки перед следующим файлом. Каждое вмешательство отмечается `VOICE_LAB_MANUAL_PREPARE` и подсчитывается в итогах; его нельзя выдавать за непрерывное нахождение модели в памяти. Неудачные/прерванные запуски сохраняются отдельно, различия температуры указываются до сравнения скорости.
